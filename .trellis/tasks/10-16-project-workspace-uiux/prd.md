# 项目工作区 UIUX 优化

## Goal

将 Trellis Panel 从功能树整理为以当前项目和当前工作对象为中心的桌面工作区：项目在窗口顶层确定一次，项目模块并列，任务或知识材料在中央完成阅读和处理，上下文按需展开。延续团队以真人操作为主的 Trellis 工作流，为后续外部集成和开发者工具保留清晰边界。

## Background and confirmed decisions

- 用户已完成多轮方案讨论，并于 2026-10-16 同意创建本版 UI/UX 任务；该同意不替代最终范围审阅。
- 业务链路是产品调研 → Jira 粗需求 → 开发整理具体需求 → 产品确认 → 技术规划 → 实现 → 技术与业务复核 → 交付 → 归档与知识沉淀。本版改善现有材料与入口的组织，不新增审批后端或改写生命周期。
- 当前导航将周期、Jira、团队、统计等不同概念归到“任务”下；用户明确否定这种层级。2026-10-16 审阅后确认保留固定窄模块栏＋可收起上下文栏，项目仍在窗口顶层；中央承载当前对象，右辅助区按需展开。
- 用户明确要求保持当前 UI 风格，并指出亮色模式层级不明显。本版沿用现有字体、品牌色、图标和组件语言，加强亮色的区域、文字和交互层级，不另换视觉风格。
- 权威边界见 `docs/proposals/2026-10-15-hifox-roadmap/05-project-workspace-and-integrations.md`；早期线框图中的侧栏项目选择器和四范围图标不再作为布局要求。
- 开发者工具的后续范围是多项目启动、基本日志查看和 Git 查看；不包含代码编辑与调试。Jira/GitLab 等按外部集成接入，本版不实现这些新增能力。

## Requirements

### R1 — 窗口顶层项目上下文

将唯一项目选择器放在普通主窗口顶栏，支持现有打开、切换最近项目和错误反馈。桌面与浏览器预览使用同一外壳结构；原生窗口按钮只在有桥时出现，交互控件不可落入拖拽区。模块标题不再重复当前项目名。文档独立窗、胶囊和速记窗沿用各自模式。

依据：`src/renderer/src/components/TitleBar.tsx:29`、`:41`，`src/renderer/src/App.tsx:181`、`:195`，`src/renderer/src/my/layout/WorkspaceSidebar.tsx:63`。未打开项目时使用真实空状态；预览数据必须明确标识。

### R2 — 固定并列导航与清晰范围

项目模块提供概览、需求接入、工作项、迭代、知识、会话、团队和统计的稳定入口；分区标题不充当可选中父菜单，不再将这些模块折叠在“任务”下。归档作为工作项的辅助视图。既有其他能力从底部工具与设置可达，不删除原有 17 个 Page 的兼容路由。应用/本机范围的 API 问答、模型和设置明确标注范围，不冒充项目会话。

固定窄模块栏放并列模块，第二栏只显示当前模块的视图或对象，不再重复全套模块或项目选择器。上下文栏可以收起，没有有用内容的模块不强行显示空栏；收起不隐藏或重排固定模块栏。该布局不改变 R1 的窗口顶层项目归属。

迭代拥有显式导航身份，继续复用现有自然周、结转与分组能力；用户仅把普通工作项按周期分组时，导航不得自动切到迭代。折叠侧栏、切模块和打开材料不改变其他主入口的位置。命令面板和快捷键同步新结构。

依据：`src/renderer/src/my/navigation.ts:17`、`:52`，`src/renderer/src/my/layout/WorkspaceSidebar.tsx:121`、`:140`，`src/renderer/src/my/CommandPalette.tsx:45`。Jira 现有查询结果不等于项目过滤结果，保留导入目标说明。

### R3 — 真实中央任务工作区与连续阅读

从工作项、个人概览、团队或材料入口进入任务后，可以真正展开为中央工作区，并返回来源，保留筛选、所选任务及列表滚动。预览与中央展开共享任务内容和现有阅读器，不能因改变布局丢弃待读新版提示、阅读基线或当前材料。

任务材料按“需求与决策 / 计划与执行 / 验证与交付”提供浏览视角，并保留全部材料、未知文件、原始 JSON/JSONL 和诊断入口。辅助区承载真实任务属性、来源、关联及观测回执，默认按需展开，窄屏不挤压中央正文。材料分组不是业务阶段，不据文件存在推断批准或检查通过。

现有缺口：`src/renderer/src/pages/TaskDetail.tsx:306` 只写展开状态；`src/renderer/src/my/layout/MyApp.tsx:166` 始终渲染抽屉；`src/renderer/src/store/slices/ui.ts:36` 的返回动作无 UI 消费者。旧 workspace 已从 `pages/Tasks.tsx` 删除，不整体恢复旧页。

### R4 — 知识围绕来源与中央阅读组织

知识检索结果与中央阅读自适应排布；规范页和知识入口复用项目文件的真实阅读能力，切到规范编辑时保留原文件定位。修复规范全文搜索/日志命中文件已加载但正文不显示的问题（`src/renderer/src/pages/Spec.tsx:424`）。不复制任务原材料来制造第二份知识。

本地项目文件、公司库、任务摘要明确来源；项目 `.trellis/notes` 使用“项目笔记”等真实称谓，不宣称私人权限。远端无 revision 契约时不显示虚构的版本固定或比较能力。公司库读取失败不阻塞本地结果。

依据：`src/renderer/src/pages/Knowledge.tsx:49`、`:130`、`:410`、`:628`，`src/main/services/knowledge.ts:257`、`:293`。

### R5 — 个人概览与团队责任视角

概览将当前可处理工作放在主位，使用“我负责 / 我创建 / 最近更新”等真实视图减少重复列表；欢迎区、统计卡和归档维护提示降级。排序与标题使用真实 creator/updatedAt 语义。

团队页按现有任务负责人、状态、未分配工作和最近记录组织，保留既有视图能力；任务 mtime 不解释为某人实际操作，不虚构在线状态、待某人批准或共享讨论。当前临时镜像评论不得被包装为正式协作记录。

依据：`src/renderer/src/my/pages/YourWorkPage.tsx:94`，`src/renderer/src/pages/Team.tsx:550`，`src/renderer/src/my/adapter.ts:118`。`TaskRecord` 无审批对象，`src/main/services/scan.ts:443` 禁止面板直接修改生命周期。

### R6 — 拓展边界与设置

保留“外部集成”和后续开发者工具的明确扩展位置，并同步既有 roadmap；入口只说明当前能力或后续计划，不制造可执行的假按钮。已有 Jira、GitLab、模型、网关和设置能力继续可达，并明确应用、项目和当前运行的实际范围。

业务/开发视角属于显示偏好，不等同权限；切换显示不启动进程或 Agent。会话继续复用现有成熟运行入口和真实 root 隔离，不新增“全部会话”作为重复主入口。

### R7 — 兼容、视觉与操作质量

沿用现有 `my.*` 令牌、主题和组件，不重做全局视觉体系。桌面、浏览器预览、浅色/深色和最小 960px 宽度下，中央内容与主要操作保持可用。保留首轮深链、项目切换竞态防护、按真实根目录隔离的收藏/视图/ACP、阅读版本提示和独立文档窗行为。

不得覆盖本轮开始前已有的未提交改动，不因外壳调整扩大到主进程运行平台或数据迁移。

### R8 — 保持风格并加强亮色层级

保持当前的绿色强调、字体、密度、圆角、图标和基础组件语言。亮色模式通过现有语义表面、结构分隔、文字主次与状态反馈，清晰区分固定模块栏、上下文栏、中央工作区和浮层。区域层级不能只靠一条极浅边线；选中、悬停、键盘焦点和不可用状态不能混淆。使用克制的阴影表达浮层，不给每个内容块增加卡片或厚重装饰。

优先正确分配现有 `my.*` 令牌，不手改自动生成的 `my-tokens.css`，不在页面散落新硬编码颜色。若真实截图仍不能区分层级，在既有主题入口集中调整亮色语义覆盖，并复核深色不回退。正文和主要导航文字以至少 4.5:1 的对比度作为本版目标，关键状态保留文字或图形辅助。

依据：`src/renderer/src/my/my-tokens.css:227–241` 已区分 canvas/layer/surface，`src/renderer/src/my/my.css:29–33` 已有 raised/overlay 阴影；应先验证消费方式，不以新增色板代替布局层级。

## Acceptance Criteria

- [ ] AC1（R1/R7）：主窗口只有一个当前项目选择器；切换项目后各模块跟随新根目录，预览/无项目状态如实表达，独立窗口模式正常。
- [ ] AC2（R2）：固定窄模块栏位置稳定，当前只有明确的一处模块选中；上下文栏只显示当前模块的视图/对象，收起不影响主模块可达；周期分组与迭代导航身份互不混淆；原有页面、命令面板和快捷键仍可达。
- [ ] AC3（R3）：工作项、概览和团队均可打开任务、展开中央、返回来源，筛选、当前项、列表滚动和原视图状态可恢复。
- [ ] AC4（R3/R7）：存在文件新版提示时，从预览展开或收回不丢失提示和阅读基线；未知材料、错误 JSON/JSONL 与原文可访问；真实回执保留原语义。
- [ ] AC5（R4）：知识和规范在 960px 与宽屏可阅读；搜索/日志命中的规范正文显示；跨页编辑能定位原文件；来源与版本能力准确。
- [ ] AC6（R5）：概览不再用两组重复长列表占据首屏；团队文案不声称实际操作者、在线状态或未经数据支持的审批职责。
- [ ] AC7（R6）：既有工具与设置可达；未来外部集成、运行/日志/Git 查看边界已记入 roadmap；本轮不新增相应后端调用或假可用功能。
- [ ] AC8（R7）：typecheck、build 及相关导航/项目隔离/阅读 smoke 通过；另做真实 UI 的展开返回、阅读版本连续性、主题和宽度走查。旧纯状态 smoke 通过不能代替 UI 验收。
- [ ] AC9（R8）：亮色截图中可辨识模块栏、上下文栏、中央内容及浮层；选中、悬停与键盘焦点可区分，正文/主要导航达到约定对比度。深色保持当前风格；新改页面没有新增零散硬编码色或全卡片化布局。

## Out of scope

新增真实审批、通知、在线协作或跨电脑共享服务；生命周期写入；外部集成平台和新 Jira/GitLab 同步；Agent 编排/新运行时；进程启动与日志平台；Git 新读写功能；代码编辑与调试；认证/角色授权；旧历史会话和无范围偏好的自动迁移。

## Risks and deferred items

- `TaskDetail` 布局重构容易卸载阅读器或来源列表，须通过实例生命周期设计及实际 UI 走查验证。
- 设置、公司知识、旧 API 问答等现有范围是混合的，本版明确标注并保留兼容，不借重命名声称完成数据隔离。
- 并行任务已修改外壳、阅读与 ACP 等文件；实施前记录基线，遇到新冲突逐项合并。
- 原生窗口拖拽/控制必须在真实桌面验证；若环境不可用，交付中列出未验证项，不以浏览器结果代替。
