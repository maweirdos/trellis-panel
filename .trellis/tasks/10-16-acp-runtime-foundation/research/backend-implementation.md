## Implemented boundary

- `src/main/services/acp.ts` now uses only the published patched `acpx/runtime` and `acpx/agent-registry` exports. The previous JSON-RPC framing, request map, shell spawning, UTF-8 buffer parsing and independent process-tree killer were removed. - Application helpers under `services/acp/` own versioned project profiles/history projection, canonical directories, input validation, sanitized errors and explicit pinned Runtime setup. Shared DTOs carry local session ID, ACP `backendSessionId`, optional native `agentSessionId`, generation and turn identity separately.
- Every session mutation and permission response receives the current project root from the main IPC wrapper and validates ownership again in the service. Profile CRUD is keyed by canonical project root. Task paths reject traversal and must identify an actual current-project task.
- Exact GUI permission mediation retains original IDs and all four kinds. Invalid choices leave the genuine request pending. Permission expiration/cancel/disconnect remove actionability and settle the owning callback. There is no session-wide remembered blanket authorization.
- Synchronous admission rejects duplicate sends and conflicting mutable directory work; idle sessions can coexist. Canonical directory identity resolves aliases/case. Known background-tool flags retain the lease until process exit; ambiguous background completion is deliberately conservative.
- Runtime discovery is asynchronous/refreshable and separates adapter installation from actual protocol/authentication readiness. Built-in Setup alone installs exact `@agentclientprotocol/codex-acp@2.2.2` or `@agentclientprotocol/claude-agent-acp@0.91.0` below userData/acp/runtimes. Start/discovery never invoke npx or install. An independently validated Node >=22.13 is selected through discovery or a native picker, with npm-cli resolved beside that Node. Legacy custom command strings retain whole-shell semantics instead of whitespace splitting; structured executable/argv stays structured.
- The host-wide `ACPX_CLAUDE_INCLUDE_USER_SETTINGS=1` policy is set before runtime construction. No credentials/provider/model configuration are copied or changed. Known authentication errors include native-login recovery guidance.
- Nonterminal state uses `acp:state`; canonical turn completion and terminal connection outcomes use `acp:done`. Both carry scope/generation/turn identity, and full terminal snapshots are typed by `AcpDoneEvent`. Startup observations represent actual launch/process/session/first-response points; no fake initialize/auth timings are inferred.
- Task-bound first-party rail events are appended only to matching task sessions; project events remain separately unbound. Old local-only histories remain transcript-only/legacy and cannot fabricate remote IDs or permissions.
- The app quit guard prevents Electron exit until delegated ACP shutdown settles, including sessions already stopping. Cleanup failure remains visible and prevents an unconfirmed clean exit.

## Explicit public API limitation: native resume

In acpx 0.19.5 `ensureSession` may select a stored persistent record without reconnecting. The same remote session is loaded at the next turn. The product does not force a dummy prompt or unrelated configuration mutation to hide this behavior. Explicit Resume verifies the stored handle/remote ID and presents `status=disconnected`, `restorePending=true` plus an observation saying native restore will be verified on send. Only `promptStarted`, after actual native load/admission, clears that flag and records verification. Failed restore keeps original history and cannot silently create/replay another session.

The raw record preserves protocol version, loadSession capability, model/config metadata and current mode. The public runtime does not expose every initialize field (e.g. full authentication-method metadata or native mode display list). Missing information stays absent; the UI must not fabricate those controls. String/select configuration controls map actual acknowledged options; unexposed boolean controls are not synthesized.
