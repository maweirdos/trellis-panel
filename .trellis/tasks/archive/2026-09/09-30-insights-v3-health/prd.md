# 任务透视 v3：任务体检+行动卡（产品化重做）

## Goal

用户二次反馈：v2 管线图"没有产品思维、还是花瓶、丑陋"。根因自省：workflow.md 的通用阶段是**框架文档**不是任务信息——把它画成图，等于把用户已知的东西复述一遍。v3 按"打开透视的用户要什么"重做：**这任务健康吗？下一步干嘛？派活弹药齐不齐？**每条信息关于本任务、每个建议带动作。

## Requirements

1. **状态带**：记录阶段 + 材料 n/6 + 问题计数（一眼健康度）。
2. **问题清单**（琥珀区）：task.json 损坏 / 阶段对应的 jsonl 缺失（"实现子代理将零规范上下文开工"）/ 超限引用计数——每条都是可行动事实。
3. **下一步卡**（规则化建议，按优先级）：planning+PRD→"可进入执行，建议先派审阅"；执行中缺 jsonl→警告；超限→"spec 拆小"；归档→引导；常驻动作按钮：复制交接包 / 去 AI 频道回看 / 派只读审阅指引。
4. **交付物清单**：每行 ✓/○ + 大小 + 缺失后果 + [阅读] 按钮（onReadArtifact 回调切工作台阅读区）。
5. **上下文体检**：两个 jsonl 的引用计数/预算百分比/判定 chip 分布 + 逐条明细折叠。
6. **会话与对话**：绑定会话（platform+最后记录）+ 本任务的审阅频道（tp-review-<dir> 前缀匹配，事件数 + [回看] 跳 AI 频道页）。

## 删除

- workflow.md 通用阶段管线图（v2，框架文档非任务信息）；
- 面包屑块预览/规则预览 tab（dev 视角，Studio 已有 workflow 编辑与校验兜底）。

## Acceptance Criteria

- [x] typecheck node+web + build 通过。
- [x] 每个区块都关于本任务：无框架文档式内容；建议均由事实规则驱动，不虚构。
- [x] 动作可用：阅读（切文档）/交接包（复制）/频道（跳页）。
- [ ] 用户目验：信息密度与"下一步"建议是否符合预期。
