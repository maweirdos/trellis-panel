# T3 交接与打开：任务交接包+编辑器直达

## Goal

落地 06 v2 T3 的核心切片：任务交接包（面板的招牌能力）与"在编辑器打开"直达入口。

## Requirements

1. **交接包构建器（services/handoff.ts）**：确定性生成，不依赖 LLM；只放索引与元信息（不复制仓库、不含凭据）；阅读清单按文件真实存在性拼装（AGENTS.md 缺失作为已知问题申报而非硬列）；已知读取问题如实写入（task.json 解析错误/PRD 缺失/工作流缺失）；尾部两行绑定要求与防重复创建（05 §5.2 模板原文）。
2. **交接包弹窗（HandoffModal）**：意图四选（只核对与阅读【默认】/审阅计划并给意见/继续实施/自定义【400ms 防抖】）；全文可预览**可编辑**后复制；附加 PRD 原文必须显式勾选且内容直接呈现在预览中（=先看到将离开本机的内容）；底部常驻"内容将离开本机"提示；已知问题行内琥珀色提示。
3. **编辑器直达**：工作台头部新增"在 VS Code / 默认编辑器打开任务目录"（复用既有 shell.openInEditor，VSCODE 环境走 vscode:// 深链）。
4. **意图措辞纪律**："继续实施"选项自带"重大范围变化先停下确认"，不因阶段生成隐含无限授权。

## 明确移出（记录）

- 元数据代跑（task.py set-branch 等按字段权限与回执）→ 与归档三段式一起在 T4 统一设计（避免与既有元数据白名单双轨混乱）。
- Cursor/Codex CLI 等更多打开适配器 → T4 后按 05 R2"两条真实链路"验证再上。
- 旧 plan.ts handoffTexts（含"完成后更新 task.json 状态"越权指引与平台硬编码命令）的清理 → 新构建器上线后随 PlanningModal 迁移处理，不在本任务扩散范围。
