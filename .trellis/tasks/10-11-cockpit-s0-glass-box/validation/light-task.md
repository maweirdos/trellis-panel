**当前状态：fixture 口径已产出（脚本 `scripts/smoke/light-task-metrics.mjs`）；真实工单录制未执行（待用户，见 §3）。fixture 数字不冒充试点数据。**

## 1. 指标口径（fixture，服务侧事件计数 / 步骤枚举）

| 指标 | 定义（本脚手架的可计量事件） | 试点目标 |
| --- | --- | --- |
| 重复录入 | 已提供过的信息需要再次录入的次数。证据事件：默认重复点击后 CLI `task.py create` 调用数与任务目录数不增加；描述由服务侧来源快照承载，链路上无二次输入点 | 0 |
| 同范围重复确认 | 同一已定事实被再次要求确认/执行的次数。证据事件：重复点击返回 `already` 直接打开、无确认弹层；Jira 流转不确定结果先查证（`already_applied`），不盲目重复 POST；多候选冲突会要求用户再次选择（计 1） | 0 |
| 新增管理动作 | 主链（创建→重复点击→归档→流转）之外、由系统引发的额外用户干预：`conflict` / `cli_failed` / `control_store` / `interrupted` / `missing` 等需人工处理或重试的结局 | ≤2 |

主链 = 用户视角的 4 个动作：① 点击「在当前项目创建任务」 ② 重复点击同一入口 ③ 本地归档 ④ 手动 Jira 流转。计量对象是这 4 步之外系统强加的额外动作，不把核心工作步骤本身算作负担。

链路环境：Jira 侧为 mock 传输层 fixture 工单（MET-101，含富文本标记完整描述）；本地侧为真实 python + 真实 task.py 副本于 fixture 仓库（git init，归档记账提交路径可达）。

| 指标 | fixture 结果 | 证据 |
| --- | --- | --- |
| 重复录入 | **0**（达标） | 重复点击后 CLI create 调用数仍为 1、任务目录数仍为 1（`already` 打开，无新建） |
| 同范围重复确认 | **0**（达标） | 重复点击 `already` 无确认弹层；流转 POST 恰一次；POST 超时后查证已达目标 → `already_applied`，单次调用内无第二次 POST（超时≠成功） |
| 新增管理动作 | **0**（达标 ≤2） | 主链 4 步全部 `ok:true`，无 conflict/cli_failed/control_store/interrupted 结局 |

计量器灵敏度（counter-example，不并入主链计数，证明计量器能发现偏差而非恒零）：

- 一单多任务后默认点击 → `conflict` 可见 → 管理动作 +1 被正确计数；
- 注入 CLI 退出码 1 → `cli_failed`（未创建≠失败）→ 管理动作 +1 被正确计数；同操作重试恢复成功。
