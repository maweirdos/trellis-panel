# 试点速览（发给 3 位同事的一页说明）

> 用途：AC10 试点启动材料。用户回复人选名单后，本页连同安装包一起转发。
> 阅读对象：2 名开发者（至少 1 名未参与本面板开发）+ 1 名需求协作方（PM/测试）。
> 周期建议：1–2 周，用自己手头的真实项目，不要求改变现有工作方式——面板是"旁挂"的，不接管任何现有流程。

## 一、安装（5 分钟）

1. 双击安装包（Windows x64，路径见转发消息，安装后桌面出现 Trellis Panel）。
2. 首次启动 → 打开你自己电脑上的一个真实项目仓库（只需本地 git 仓库，不需要联网授权）。
3. 面板数据全部落在本机（项目 `.trellis/.panel/` 下），不含代码原文上传，卸载即净。

## 二、各自看什么（按角色）

**开发者 A/B（重点：读文档 + 任务上下文）**
1. **统一阅读**：在面板里打开项目的 PRD/design/spec Markdown，改窗口宽度、按 Esc 逐层退出、外部改文件后看"当前阅读任务有更新"提示——对照你平时开 Typora 的体验，记下不顺手的地方。
2. **上下文回执**（可选，需在设置里启用观测绑定）：跑一次你的 AI 编码会话并派发子代理，在面板"观测"页看上下文回执（哪些材料真被注入了、截断了多少）。看不懂没关系，记下"看不懂"本身就是反馈。
3. **对照走查清单**：validation/reader.md §4、validation/observability.md §5（转发时可截图附上，不需要他们看仓库）。

**需求协作方 C（重点：Jira → 本地任务）**
1. 在面板 Jira 页（配置好公司 Jira 后）找一张自己提的、正在被开发的工单，点"在当前项目创建任务"。
2. 看生成的 PRD 草稿：描述是否完整、来源链接是否可点、有没有"待确认"的空段落。
3. 之后隔天回来看：能否看到开发侧进度（不用问人）。

## 三、反馈怎么给（每人 10 分钟）

直接回消息给转发人，按下面三行 + 随意补充：

```
1. 顺手程度：每天大概会打开几次？有没有哪个功能你打开一次就不想再开？
2. 卡点：哪里看不懂/点不动/和你预期不一样？（截图最好）
3. 维护意愿：如果这个小工具由团队维护，你愿意每周花几分钟更新它吗？
```

度量口径（light-task.md，由面板侧自动记录，不需要同事填）：新增重复录入 0、同范围重复确认 0、新增管理动作 ≤2。

## 四、边界说明（如实，不藏着）

- 观测回执默认关闭；开启后也只记录"哪份材料被注入/多大/结果"，不含代码原文与完整 prompt。
- 团队级分发（其他仓库自动获得 hook 更新）依赖上游 PR，尚未发起——试点版是本机完整功能。
- 已知限制清单：research/known-issues.md（转发时可摘录环境类两条）。
