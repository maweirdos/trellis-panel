# 驾驶舱 S0：统一阅读、上下文回执与可信活动

版本：v2 · 2026-10-11 · 阶段：planning。按用户本轮要求修订规划；功能与发布检查尚未执行。

## 1. Goal

让员工继续在自己的电脑和熟悉的 AI 编辑器中开发，同时在 Trellis Panel 中读清任务资料、查看本次上下文输出的可观察证据，并从 Jira 工单进入本地任务，减少重复整理。

首版回答三个问题：

1. PRD/设计被 Agent 持续修改时，我能否舒适阅读并看懂变化？
2. 哪些材料只是列在计划里，哪些已经组装或输出，哪些目前不知道？
3. 工单、本地任务、归档与 Jira 流转是否增加了重复录入和无用操作？

S0 是团队平台的本机基础，不把个人面板称为已经完成的团队实时平台。

## 2. 已确认的背景与边界

- 团队约 12 人、8 名开发；用户能推动全团队，工作日使用。维护人员与开发时间未确认，不能把使用五天理解为每周五天建设产能。
- 代码和 Agent 执行在员工本机；沿用现有模型使用方式，平台不额外上传或镜像仓库。
- 产品成员可澄清业务、查已发布规范与知识；本机代码上下文由开发绑定仓库后补充。业务材料不冒充已经完成技术分析的 PRD/design。
- 沿用用户提供的当前 UI：浅色工作台、现有导航、白色内容区和蓝绿强调。此前概念原型不作为验收依据。
- 试点建议 2 名开发（至少 1 名不是建设者）＋1 名需求协作者；人员和公司访问条件在试点前落实，不阻塞本轮文档修订。
- 沿用既有任务 ID 与目录，不另建任务，不在规划期间切换为 in_progress。

原始痛点见 [用户痛点证词](../../../docs/proposals/2026-10-11-cockpit-counter-proposal/01-user-pain-points.md)；代码依据见 [R01–R12 审查](review/01-approval-review.md)，修订映射见 [修订记录](review/04-revision-resolution.md)。

## 3. 用户场景

| 场景 | 用户可观察的结果 |
| --- | --- |
| 开发读设计，Agent 在后台保存新版 | 当前正文、选区和位置不突然变化；提示有新版，可先看差异再切换 |
| 开发怀疑规范未提供给 Agent | 分别查看计划清单和实际回执，知道裁剪、仅索引或不可读；不以有文件代表被遵守 |
| 开发处理 Jira 小修复 | 自动带入工单资料、明确当前项目、打开已有本地关联，避免重复创建 |
| 评审者查看进展 | 分清任务记录、真实活动、归档和外部系统状态；未知信息不会显示成功 |
| 产品或接手者参加试点 | 阅读明确发布/导出的材料版本，确认范围和未决问题；不承诺跨机器实时草稿 |

## 4. Requirements

### FR1 · 统一阅读与版本比较（P01；R01/R07/R09/R10）

- Tasks 工作区、TaskDetail 快速预览和 ArtifactViewer 使用一致的解析与阅读行为；预览可展开为完整任务工作区并保留返回位置。
- PRD/design/implement 支持目录、最大阅读宽度偏好、专注与原文；文件尚未创建有明确空态。
- task.json 展示常见属性和未知字段；原始文本始终可见，解析失败不丢原文。
- implement.jsonl/check.jsonl 是**上下文清单**：材料路径、用途、顺序、来源、当前可读性。不提供运行时间或成功证据；坏行保留原始行号，空行不改变编号。
- 外部变化提示“发现新版本”，由读者选择比较或阅读新版；读取失败保留旧版并提示。普通任务属性变化不重载正文。
- S0 支持“与本次打开版本比较”和“与最近提交比较”；前者覆盖未提交草稿。无 Git 基线有说明，不影响草稿比较。跨重启草稿历史、任意两个历史提交选择器后置。
- 1280/1440/1920 CSS 像素与高缩放下可用；窄窗口不强迫三栏并排。焦点、Esc 层级和正文选择符合预期。

### FR2 · 真实、有界的上下文回执（P02；R02/R04/R05/R06/R11）

- 首发认证一个真实宿主与 Hook 组合，显示组装和成功输出两类事实；最高措辞为**“已输出至宿主通道”**，不宣称宿主确认、模型已注入或规范已遵守。
- 同次注入关联其材料、工作区、任务与已知会话；同一父会话的并行子 Agent 不串线。无法确定任务时保留未归属记录，不绑定当前任务猜测归属。
- 区分完整纳入、裁剪、仅索引、缺失/不可读，显示当时材料摘要和明确字节口径；清单不完整须显示遗漏数。
- 观测失败不改变正常 Hook 输出，不重复输出；只显示已记录事实。无记录默认“未观察到”，明确诊断才支持故障提示。
- 记录有容量、保留、恢复和兼容机制；面板关闭也不会无限积累。用户可查看观测健康状态、禁用和清理本机记录。
- 支持、安装、启用和版本兼容状态清楚可见；实验性修改本机 Hook 不算团队分发完成。

### FR3 · 可信任务活动与来源（P02/P03；R03/R04/R07）

- 分开显示任务记录状态、最近观察活动、归档位置，保留自定义状态原值。
- 事件有来源、时间和关联范围；文件保存只说明文件变化，检查 Agent 启动不等于检查通过。
- 只有显式且可解释的阶段开始/结束证据才显示该活动及持续时间；不从 task.status 或 mtime 生成六阶段完成链。
- 项目级规范变化不混入某个任务轨道；切换项目/任务、归档和多个 worktree 不串线。
- 本地完成、Jira 状态和检查结论独立展示，不强行互相覆盖。

### FR4 · Jira 到本地轻任务（P05；R08）

- 从本人已分配工单进入当前项目，带入完整可取得的描述、稳定来源标识和更新时间；换仓库须显式选择。
- 统一本地创建行为，写入 task.json、最小 PRD 草稿和来源关联；草稿标“待结合本机代码确认”。
- 重复点击优先打开已有任务；一单多任务允许显式新增。创建中断后可恢复，不制造重复任务或无法辨认的半成品。
- S0 不新增 Jira assignee 认领 API；入口称“在当前项目创建任务/打开本地任务”。
- 本地归档与手动 Jira 流转分别反馈；远端超时先核实当前状态再决定重试，不宣称自动同步成功。
- 计量新增重复录入、同范围重复确认、新增管理动作；试点目标为 0、0、≤2，尚待实测。必要阅读/编码/外部等待单列。

### FR5 · 基线、回归与跨人试点（R08/R11/R12）

- 采集两个指定 Jira 版本的类型分布，记录查询、时间、实际数量/服务端总数、版本范围、多版本计数规则和完整性；不全则标样本。
- 测量观测开关差值、并发/锁冲突、面板关闭、冷启动、长期运行；结论包含是否达到设计试验预算及调整措施。
- 本地核心可用后尽早带入第二位开发与需求协作者，验证阅读、材料交接和新增负担；记录维护者实际适配/故障处理时间。
- 无公司访问条件时可记录本地能力已通过，但外部验收保持待验证；模拟数据不冒充真实基线或团队试点。

## 5. Out of Scope

S0 不建设团队实时服务、云端开发、组织调度、远程替员工启动 Agent、自动多 Agent 派单或替代任务界面的通用聊天产品。

还不做：全宿主认证、宿主接收确认、规范遵守证明、固定步骤遗漏检测、受管批准门、自动 Jira 同步队列、新 assignee 认领、GitLab MR/CI 聚合、飞书接入、跨设备草稿同步、跨重启文档历史、任意提交历史选择器、新知识库/模型网关、Electron 换壳。既有 ACP/MCP/模型能力保持可用，后续边界见 design。

## 6. Acceptance Criteria

每项记录输入、实际结果与证据位置；清单存在不等于已经执行。

| ID | 需求 | 可观察的通过结果 |
| --- | --- | --- |
| AC1 | FR1 | 三入口内容一致；JSON 常见/未知字段及原文可见；清单无虚构时间；坏行保留真实行号 |
| AC2 | FR1 | 连续保存不重置阅读/选区；可比较会话草稿及最近提交；无 Git、缺文件、坏文件、写入中均有明确状态 |
| AC3 | FR2 | 真实认证宿主的 assembled/emitted 可配对；输出失败无 emitted；观测失败不改变 stdout；材料、摘要、字节、不完整标识可核对 |
| AC4 | FR2 | 并发、重复、锁冲突、中止、只读/满盘、容量和旧 schema 符合设计；可禁用/恢复；未知与明确故障可区分 |
| AC5 | FR3 | 多任务/项目/worktree、切换、归档、未归属事件不串线；状态/活动/归档独立；不伪造阶段通过或耗时 |
| AC6 | FR4 | 同工单重复点击和中断重试可恢复；PRD 来源真实；归档与 Jira 流转分别确认；轻路径计量有真实操作 |
| AC7 | FR5 | 两版本 Jira 报告有完整性；真实 Hook 性能报告有样本、预算和结论；缺公司条件维持待验证 |
| AC8 | 全部 | typecheck/build、相关既有与新增测试通过；Tasks/TaskDetail/ArtifactViewer/AcpConsole/Jira 无已知回归；三档尺寸、焦点/Esc 有证据 |
| AC9 | FR2 | 干净及有用户 Hook 修改的项目验证安装/升级/禁用/回退；能力显示真实；另一开发可按同一路径接入 |
| AC10 | FR5 | 2 名开发＋1 名需求协作者完成试点；材料版本/时效明确；新增负担和维护时间有记录及处理结论 |

本地验收与完整 S0 发布分开：AC1–AC5/AC8 的局部通过不能替代 AC6/AC7 公司环境、AC9/AC10 分发与试点。发布不得将待验证项目勾成完成。

## 7. Constraints 与规划状态

- Trellis 文件仍是任务资料权威来源；观测数据不反向覆盖任务或外部系统事实。
- 回执默认本机私有，不含原始代码、完整 prompt 或密钥；团队分享显式选择材料版本。
- 保留现有 UI 与本机架构；允许可靠存储、协议校验和差异比较使用适合的成熟组件，选型见 design，不限制只能新增一种依赖。
- 维护投入、试点人选、公司 Jira 版本/权限、上游 Hook 发布条件列为技术/发布依赖，不据此扩大承诺。
- 用户已授权本轮优化文档。现有范围足以完成修订；本轮不启动实现，功能验收保持未执行。
