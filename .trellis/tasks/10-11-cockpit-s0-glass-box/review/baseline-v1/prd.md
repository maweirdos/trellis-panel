# 驾驶舱 S0：阅读中枢、注入回执与阶段观察

## Goal

按收敛方案（`docs/proposals/2026-10-11-cockpit-convergence/`，辩论 01–05 轮 + 06–08 章，用户已批准方向）交付首个实施包 S0：把 trellis 执行过程从"文件结果"升级为"可看、可评、可续的界面"的第一层——**玻璃盒**。S0 只回答三个问题（06 章第 3 节）：

1. **读得舒服吗？** PRD/design/task.json/implement.jsonl 的结构化阅读。
2. **我到底知道什么？** 注入回执（第 1/2 类证据：已组装 → 已交付至宿主）。
3. **比现在多做了什么无用操作？** 轻任务样例的操作负担计量。

## 背景与用户

- 用户痛点证词：`docs/proposals/2026-10-11-cockpit-counter-proposal/01-user-pain-points.md`（P01–P09）。
- 首发用户：建造者本人；首轮试点随后带入 2 名开发（至少 1 名非建造者）+ 1 名需求协作者（08 决策第 2 项，人选待用户指定，不阻塞 S0 开发）。
- 团队事实：约 12 人、8 开发、可推动全团队、工作日使用；维护投入未确认——建设按单维护者预算。

## Requirements（S0 范围内）

### FR1 阅读中枢（F1 补全，P01）

- PRD/design 阅读体验：可调阅读宽度、专注模式、版本差异视图；文档内目录导航。
- task.json 结构化卡片：状态/阶段/父子关系/分支等字段卡片化；原始 JSON 始终可展开查看，**原值不丢、未知字段不隐藏**。
- implement.jsonl / check.jsonl 时间线：逐条时间轴卡片（时间/类型/摘要），可按类型筛选。
- 更新不抢焦点：文件变化触发刷新时保持滚动位置，提示"有新版本"而不自动跳转。

### FR2 注入回执（F2 第 1/2 类证据，P02）

- hook 落账：上下文组装完成、交付宿主通道两个时机各产生一条事件（含文件清单、hash、字节数、截断/裁剪标记、目标任务、目标会话）。
- 回执卡片 UI：规范清单表 + 汇总条（共 N 条 / 截断 M / 缺失 K）；证据等级最高显示"已交付至宿主"，**不得显示"已注入模型"**。
- 有界记录：hook 内只做轻量片段写，不等待网络、不做重型扫描；遥测失败不阻断上下文交付，降级为可见的"回执缺失（仪器故障）"灰卡。
- 逻辑日志出口：片段文件由收集器顺序合并为按日 JSONL 日志；崩溃残留片段可回收；未持久化成功的事件不得显示为已落账。

### FR3 工作流阶段观察（F3 阶段级，P02/P03）

- 任务阶段管道：未开始 → 规划 → 实施 → 检查 → 完成 → 归档（读取 task.json 状态与 jsonl 事件），当前阶段高亮并显示最后事件时间。
- 任务身份不串线：修复 `emitTrellisTimeline` 部分事件缺失 taskDir 的关联缺陷；无任务归属的事件不进入任务管道。
- 未知 ≠ 未执行：无证据的阶段/步骤显示"未知/未观察到"，不显示为"未执行"，不用红色。

### FR4 轻任务样例（F17 的 S0 部分，P05）

- 定义并录制一个轻任务操作脚本：Jira 认领 → 本地建轻量任务 → 关联工单 → 归档回写。
- 计量口径按收敛结论：新增重复录入 0、同范围重复确认 0、新增管理动作 ≤2（候选目标，非承诺）；必要阅读/编码/外部等待单列不计。

### FR5 基线测量（为后续预算提供真数）

- Jira 两个大版本的 issue 类型分布基线（复用现有 jira.ts，按 fixVersion 聚合）。
- hook 观测开销基线：回执开关 on/off 对比，记录 p50/p95/最大增量；不预设 <100ms/<50KB 为验收值。

## Out of Scope（本任务不做）

- S1 驾驶舱交互（权限卡/确认门/钉规范/前情提要/子任务树）——仅留设计骨架（见 design.md 第 7 节）。
- S2/S3（Jira 版本看板增强、GitLab MR/CI 对齐、飞书三档、实时服务、静态站）。
- 步骤级工作流遗漏检测（阶段级先行）；全 Agent 适配（首发只验证一个真实宿主/Agent 组合）；宿主接收确认级证据（第 3 类）；检查关联（第 4 类）。
- 平台验收流、组织账号、多设备任期、Brief 写作面（08 决策第 6 项后置清单）。
- Electron → Tauri/Web 壳改造。

## Acceptance Criteria

验收口径 = `06-feasibility-and-pilot.md` 第 3 节三问 + 第 5 节 S0 阻断项 + 第 7 节技术验证卡。可观察结果：

- [ ] AC1（FR1）：在一个真实历史任务上，PRD/design/task.json/implement.jsonl 全部可舒适阅读；task.json 未知字段与原值可见；文件外部修改后视图刷新且不丢滚动位置。
- [ ] AC2（FR1）：损坏 JSON、未知状态、写入中的文件不崩溃、不静默消失（06 验证卡"文件阅读"行）。
- [ ] AC3（FR2）：一个真实宿主/Agent 组合下，组装与交付两级回执可见，含文件/hash/字节/截断；卡片措辞无"已注入模型"。
- [ ] AC4（FR2）：注入失败、进程退出、断线场景下回执缺口可见且有诊断（06 验证卡"回执完整性"行）；遥测故障不阻断正常 hook 输出。
- [ ] AC5（FR3）：阶段管道正确反映任务状态；同项目多任务事件不串线；无证据显示"未知"。
- [ ] AC6（FR4）：轻任务脚本全程可演示；计量表按口径产出。
- [ ] AC7（FR5）：两个基线报告产出（数字与样本来源标注）。
- [ ] AC8：无回归——现有 Tasks/TaskDetail/AcpConsole/Jira 功能不受破坏；`trellis check` 通过。

## Constraints（继承收敛边界）

- 代码与执行留在本机；不新增仓库上传；模型使用方式不变。
- 防伪原则：缺证据不升级状态；文件被读过 ≠ 规范已遵守。
- hooks 修改走 trellis 模板升级路径（trellis-meta），不私改各项目副本。
- 新增依赖最小化（仅 schema 校验库）；不引入数据库/服务。
