## 2. 与上轮建议相比进一步收敛的地方

- S0 文档对比只承诺本次阅读会话与最近提交。任意两次提交选择器、跨重启草稿历史后置，避免实现者替模糊的“上一版”自行扩张范围。
- 首发明确为 Codex 原生 SubagentStart 的上下文 Hook；workflow-state 的预算/输出契约不同，本轮不混用两种记录形态，其他宿主不借其结果背书。
- 数据库指导中 Drizzle/better-sqlite3/WAL 示例与实际依赖不一致，已登记 D-SQLITE 的适用差异，保留事务与迁移要求；不为最少依赖而省掉可靠性。
- 复核后将可降级观测与本地任务控制记录分到 observations.sqlite/control.sqlite。观测禁用、配额、清理、损坏均不能删除任务恢复记录；控制记录不能落盘时禁止创建副作用，控制恢复有备份/来源对账与人工确认边界。
- 复核统一事件/数据库/IPC 为项目规定的 Unix 毫秒；并按真实 CLI 的日期目录行为补跨午夜恢复，通过 create --meta 在首个 task.json 写入时携带 operationId，不靠后补标识或 --force 覆盖。
- 本机绑定补仓库外 installationId，覆盖另一机器相同路径的仓库复制；Jira 描述明确为 PRD 保留取得的完整规范化正文，摘要只供简介/索引，不完整时须提示。--meta 按实际 CLI 的扁平 key=value 字符串使用。
- 快速阅读可先交付，但完整 S0 发布还要通过真实 Jira、跨员工分发和试点；没有环境就保持对应项目未完成。
- 没有新增实现代码、任务或第三套 UI 原型。旧审查按原快照理解，当前交付以 v2 三份文档为准。
