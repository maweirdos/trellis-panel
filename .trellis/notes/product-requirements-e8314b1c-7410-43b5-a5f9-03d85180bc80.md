# 皮试医嘱业务需求文档

版本：V0.1  
文档状态：待业务评审  
编制日期：2026-10-20  
适用读者：产品、业务、开发、测试及医护业务负责人

## 1 需求背景与目标

皮试相关医嘱涉及医生开立、护士核对与执行、结果录入和多个业务界面的结果展示。系统需要保持关联医嘱提交行为和皮试状态表达一致，使相关人员能够识别免试、结果未出、阴性与阳性，避免将空白结果误认为阴性。

本需求以住院皮试流程为主，补充门诊已明确的状态展示要求。文档中的“资料明确”表示原手册摘录支持该规则，不代表功能已经实现或验收通过；“业务串联”用于说明流程关系；“待确认”事项须经业务评审后确定。

## 2 需求范围

### 2.1 本次范围

- 住院皮试相关医嘱的关联提交。
- 住院护士医嘱核对界面的皮试标识与结果展示。
- 住院皮试结果首次录入和有权限人员的结果修改。
- 医生站、护士站、医嘱单打印及相关门诊界面的状态回显。
- 统一的皮试状态展示规则与可验证的验收标准。

### 2.2 待确认后纳入的范围

医嘱自动生成、免试判定条件、实际皮试执行操作、未出结果或阳性时的用药拦截、结果有效期、跨就诊复用、门诊缴费与取药顺序、撤销与退费联动均未形成已确定规则。本版列出这些问题，不将其作为已批准的实现要求。

本文件描述 HIS 业务需求，不规定皮试操作方法、药品剂量、观察时间或临床结果判定标准。

## 3 角色与职责

| 角色 | 业务职责 | 确定程度 |
| --- | --- | --- |
| 住院医生 | 开立、提交皮试相关医嘱，查看皮试状态与结果 | 资料明确 |
| 住院护士 | 在医嘱核对界面查看状态，选择医嘱并录入皮试结果 | 资料明确 |
| 有结果修改权限的人员 | 对已录入的错误结果作修改 | 资料明确；具体角色与授权方式待确认 |
| 门诊医生及治疗执行人员 | 在相应业务界面查看皮试状态 | 资料明确；门诊完整操作流程待确认 |
| 门诊收费人员 | 在缴费申请单相关界面查看皮试状态 | 资料明确 |

权限配置的维护主体、首次录入权限范围及是否需要双人复核，见待确认事项。

## 4 业务对象与状态

### 4.1 业务对象

- **皮试药**：关联的治疗用药，提交规则中称为皮试药。
- **皮试液**：皮试流程涉及的关联药品医嘱。
- **皮试**：关联的皮试医嘱或项目。
- **皮试结果**：与患者及对应医嘱关联的结果记录。
- **是否皮试**：决定界面按免试或待结果等状态显示的业务选项。

前三类对象的具体目录分类、关联方式和生成方式须结合完整医嘱开立规则确认，不能仅凭上述名称推定具体配置。

### 4.2 状态展示规则

| 是否皮试 | 结果情况 | 显示内容 | 业务含义 |
| --- | --- | --- | --- |
| 否 | 不适用 | 免试 | 按免试状态展示 |
| 是 | 结果未出 | 空白 | 尚无皮试结果 |
| 是 | 阴性 | 阴性（-） | 已录入阴性结果 |
| 是 | 阳性 | 阳性（+） | 已录入阳性结果 |

空白结果与阴性结果必须区分。免试不是阴性结果，其判定条件和权限另行确认。界面显示状态也不等同于医嘱提交状态、执行状态或用药放行状态。

## 5 业务流程

### 5.1 住院主流程

医生开立皮试相关医嘱 → 保存与关联提交 → 护士核对 → 皮试执行 → 护士录入结果 → 各业务界面及医嘱单回显。

该顺序用于串联业务。资料明确描述了关联提交、结果录入及回显规则；护士核对与实际执行的详细前置条件、操作步骤及完成状态未在当前摘录中展开。

1. 医生为患者开立皮试相关医嘱。是否自动带出皮试液和皮试项目，待确认。
2. 住院采用勾选提交时，系统先保存，再提交。勾选皮试药、皮试液、皮试任一项或任意组合，均一起提交相关三类医嘱。
3. 护士在医嘱核对界面查看皮试标识与当前结果状态。
4. 皮试执行后，护士选择尚未录入结果的单条医嘱，点击【皮试结果录入】，填写并保存结果。
5. 系统在相应业务界面和医嘱单打印中显示结果。
6. 结果录错时，有结果修改权限的人员可修改结果。

阴性后继续原用药流程、阳性后由医生评估治疗方案属于业务理解。系统是否自动放行、拦截、停止或调整医嘱，须另行确定。

### 5.2 门诊范围

已确认门诊医生站、门诊治疗单执行、门诊收费缴费申请单相关界面需要展示皮试状态。现有资料不足以确定门诊开单、缴费、取药、皮试执行、结果录入及治疗执行的完整先后顺序，不能直接套用住院提交规则。

## 6 功能需求

### FR-01 住院关联医嘱提交

**依据：S1，资料明确。**

住院医嘱提交方式由参数控制：全量提交方式提交未提交医嘱；勾选提交方式提交勾选医嘱。采用勾选提交时须先保存、再提交；对皮试药、皮试液、皮试，勾选任一项或任意组合均一起提交。

提交仍须遵循既有库存、必填项和权限校验规则。关联医嘱缺失、失效以及保存或提交失败时如何处理，见 Q08。本版不推定后台事务、失败补偿和重试机制。

### FR-02 护士核对界面展示

**依据：S2、S3，资料明确。**

住院护士站医嘱核对界面显示皮试药品标识“皮试”，并按第 4.2 节显示免试、空白、阴性或阳性状态。皮试液、皮试、药疗相关的皮试药品均须按资料要求展示状态，显示位置在对应皮试药品左侧并紧邻药品名称。

### FR-03 首次皮试结果录入

**依据：S2，资料明确。**

在住院护士站医嘱核对界面，护士单选尚未录入结果的医嘱后，可通过【皮试结果录入】打开弹窗。弹窗中药品名称取自对应医嘱的 ITEM_NAME，且不可修改。系统支持录入阴性或阳性结果并保存，使对应医嘱能够回显结果。

本版确定单条医嘱首次录入路径，不扩展批量录入。结果录入的其他必填字段、执行状态前置条件、复核和并发规则见待确认事项。

### FR-04 皮试结果修改与权限

**依据：S2，资料明确。**

对录入错误的结果，有权限人员能够修改；无结果修改权限的人员不能成功修改结果。具体授权角色、修改入口、可修改字段、修改时限、修改原因、是否复核和历史记录要求须经业务确认。

首次录入与结果修改是不同操作，不应将首次录入路径视为绕过修改权限的依据。

### FR-05 各业务界面及打印回显

**依据：S2、S3，资料明确。**

| 业务界面或输出 | 展示要求 |
| --- | --- |
| 住院医生站医嘱面板 | 展示对应药品的皮试状态 |
| 门诊医生站医嘱面板 | 展示对应药品的皮试状态 |
| 住院护士医嘱核对界面 | 展示皮试标识和皮试状态 |
| 门诊治疗单执行界面 | 展示相关皮试状态；完整布局待确认 |
| 门诊收费申请单加载界面 | 展示对应药品的皮试状态 |
| 门诊收费申请单明细界面 | 展示对应药品的皮试状态 |
| 医嘱单打印 | 展示对应皮试结果 |

各界面统一使用第 4.2 节的状态含义。结果首次录入或修改后，应能查询和展示对应结果；刷新方式、更新时限和已打印单据处理方式见 Q10。

### FR-06 结果与业务对象关联

**依据：S2、S3，资料明确；业务关联要求由录入与回显流程归纳。**

结果必须能够对应到正确患者及相应医嘱、药品，支持护士录入、授权修改和各界面回显，不得把其他患者或其他医嘱的结果误用于当前对象。

资料涉及 EMR.CPOE_PATI_ALLERGY_RECORD 患者过敏信息记录表。该表仅作为已有数据依据，具体主键、关联字段、结果编码和记录粒度由后续设计确认，本需求不新增数据库字段约定。

## 7 业务规则汇总

| 编号 | 规则 | 依据 |
| --- | --- | --- |
| BR-01 | 住院勾选提交时，皮试相关三类医嘱任一或组合勾选均一起提交 | S1 |
| BR-02 | 住院勾选提交须先保存、再提交 | S1 |
| BR-03 | 是否皮试为否时显示免试；为是且结果未出时显示空白 | S2、S3 |
| BR-04 | 结果已出时，按阴性（-）或阳性（+）显示 | S2、S3 |
| BR-05 | 首次录入通过单选尚未录入结果的医嘱发起 | S2 |
| BR-06 | 结果录入弹窗的药品名称来自对应医嘱，不可修改 | S2 |
| BR-07 | 错误结果支持有权限人员修改 | S2 |
| BR-08 | 医生站、护士核对、相关门诊界面和医嘱单按适用范围回显结果 | S2、S3 |

上述规则不包含临床免试条件、结果有效期或自动用药控制。

## 8 验收标准

以下为本需求的验收条件，尚未执行验收。测试需准备具有关联关系的皮试药、皮试液和皮试医嘱，以及具有和不具有结果修改权限的账号。

| 编号 | 前置条件或操作 | 预期结果 | 对应需求 |
| --- | --- | --- | --- |
| AC-01 | 勾选提交模式，分别仅勾选皮试药、皮试液或皮试，及勾选两项或三项组合 | 相关三类医嘱均按关联提交规则处理 | FR-01 |
| AC-02 | 勾选提交模式，对尚需保存的皮试相关医嘱执行提交 | 先完成保存，再提交；不能用仅有界面变化代替提交成功 | FR-01 |
| AC-03 | 分别准备免试、结果未出、阴性和阳性数据 | 显示依次为免试、空白、阴性（-）、阳性（+），无混淆 | FR-02、FR-05 |
| AC-04 | 在护士核对界面单选尚未录入结果的皮试医嘱，点击结果录入 | 打开对应弹窗，显示正确药品名称，药品名称不可编辑 | FR-03 |
| AC-05 | 分别保存阴性与阳性结果 | 重新查询后，对应患者与医嘱显示所保存结果 | FR-03、FR-06 |
| AC-06 | 使用具有结果修改权限的账号修改已录入结果 | 修改成功后，重新查询显示修改后的结果 | FR-04 |
| AC-07 | 使用没有结果修改权限的账号尝试修改已录入结果 | 不能成功修改，原结果保持 | FR-04 |
| AC-08 | 对 FR-05 列出的适用界面重新加载数据，并打印医嘱单 | 展示或打印正确状态与结果，符合各界面适用范围 | FR-05 |
| AC-09 | 准备不同患者、同一患者不同医嘱的结果数据并交叉查询 | 各结果对应正确对象，不发生串用 | FR-06 |
| AC-10 | 在未出结果的数据上查询各适用界面 | 不把空白显示或解释为阴性、免试或已放行 | FR-02、FR-05 |

涉及用药拦截、免试条件、结果有效期等场景，须在对应问题确定后补充验收标准。
