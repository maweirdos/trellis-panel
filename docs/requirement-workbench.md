# 需求工作台

## 工作路径

普通 Work／Code 对话中的“新建需求”打开完整需求工作台，左侧为文档，右侧为需求助手。导航、个人和团队页面保留各自的功能。关闭工作台后恢复原对话、未发送文字、图片及所在分组。

需求按以下顺序流转：

1. 输入想法，或明确带入当前输入、参考当前对话。
2. 检索选定知识库，核对来源，回答澄清问题。
3. 生成并编辑需求文档，补充范围与验收条件。
4. 确认保存的需求版本，生成独立计划。
5. 编辑计划，选择实际 Trellis 工程，确认创建任务和固定输入。
6. 核对执行引擎，激活任务并准备原生执行会话，在现有 Trellis 工作流中预览并确认启动。

个人需求的整理、知识检索和文档编辑不要求加入团队空间、选择工程或初始化 Git。工程仅在向本地 Trellis 任务交接时选择。团队发布、评审、设计与开发安排继续使用现有业务流程，不共享私人原始会话。

该路径承接 [端到端产品流程 F17](./product-flow-interaction-prd.md#f17-客户需求到标准需求与业务确认)：原始诉求、现有能力证据、少量关键问题、可编辑业务稿、固定版本及明确下一步。个人草稿的确认不等同于团队评审通过，生成计划不等同于开始实施。

## 文档与助手

“需求”和“计划”是两份独立文档。正文使用阅读排版，支持格式编辑、撤销、选区引用和针对引用的修改。复杂 Markdown 不能完整往返时，保留原文并使用源码编辑；格式转换不能悄悄删除内容。

需求助手的输入与普通对话草稿分开保存。执行引擎、模型、权限和停止操作复用原私有原生会话。每项需求操作按其真实 request、session、connection generation 和 turn 展示，普通对话的其他运行不混入需求助手。

“澄清问题”“研究资料”“生成需求”“修改文档”“检查验收”“生成计划”和继续讨论均有固定输入与实际输出。原生引擎写入完整候选文件且该回合确认结束后，才允许采用。原文和本地编辑未变化时，工作台采用本次明确操作生成的候选作为草稿；已发生编辑或版本变化时，保留候选并提供可读比较，不覆盖新内容。

助手内部的控制提示与普通用户消息分别记录。界面显示用户输入或操作名称，完整展开提示保留在原生诊断信息中。不得把内部提示、示例模型或组件验收文字显示为产品内容。

## 知识来源

知识来源使用已有集成连接。用户选择连接、连接修订和知识库范围后检索，再选择明确的返回来源。未连接、无权限、查询失败和没有结果分别表达，不能将失败视为空结果，也不能默认查询全部知识库。

每个采用的引用保留连接、库、文档身份、返回摘录、内容摘要、截断信息及时间。`returnedRevision` 标识本次实际返回的摘录和范围，不代表上游完整文档版本。操作开始前封存选定来源，恢复时核对原快照，不以重新检索的最新内容替代旧输入。

知识资料、文件和对话片段是参考内容，不能授予工具权限、启动工程或发布产物。私人对话片段仅用于本人需求澄清，正式任务接收已采用文档与明确选取的材料。

## 计划与 Trellis 任务

“下一步”先保存并固定需求版本，再据此生成单独的 `plan.md`。需求变化后，原计划保留并标记需要更新。未确认需求、计划过期、实际文件与已保存摘要不符时，不能交接另一版本。

交接使用现有任务创建器，生成 `planning` 任务、`prd.md`、`plan.md`、确认快照及材料来源清单。部分写入失败沿原 command、任务身份和固定版本补齐，不重建同名任务或覆盖已有不同正文。

执行准备使用官方 `task.py start` 及既有工作副本和原生命令守卫。退出码为零不能代替实际任务状态和所属上下文指针的验证。准备生成普通工程会话作为工作流 origin，不能改挂原私人会话目录，也不能把私有别名当成工程执行会话。

执行会话就绪后，交给现有工作流的预览、启动、阶段、权限、产物与恢复能力。准备就绪、工作流运行、阶段产物核验、开发完成和业务验收分别表示，不互相代替。

## 保存与异常

文档保存同时核对元数据修订和实际文件摘要。首次原生身份绑定与文字保存并发时，重复相同运行时或模型字段不能阻断文字保存；实际更换执行引擎、模型或目录仍走原有准入规则。

同一阻断原因只占一处紧凑提示，保留对应恢复入口，原始错误和诊断按需展开。操作失败后保留文档、输入、答案、引用与原请求。未知发送或准备结果只核对原回执，不能自动重发、另建会话或显示成功。

## 设计约束与来源

工作台遵守 [DESIGN.md](../DESIGN.md) 与共享 CSS 规范：固定 10px 普通圆角、三档密度、名称与描述层级、独立阅读字号、键盘焦点、轻微图标 hover 和减少动态效果。富文本编辑器按需加载，不加入普通聊天首屏。

交互参考 Kun 的 [文档编辑工作面](https://github.com/KunAgent/Kun/blob/0d8406128e2cede3bb5085c2d28fb90ab9e91f69/src/renderer/src/components/sdd/SddDraftEditorView.tsx)、[文档旁助手](https://github.com/KunAgent/Kun/blob/0d8406128e2cede3bb5085c2d28fb90ab9e91f69/src/renderer/src/components/sdd/SddAssistantPanel.tsx)和[需求到计划控制器](https://github.com/KunAgent/Kun/blob/0d8406128e2cede3bb5085c2d28fb90ab9e91f69/src/renderer/src/components/workbench/useWorkbenchSddTurnController.ts)。任务、材料版本及原生执行仍由本项目既有契约管理。
