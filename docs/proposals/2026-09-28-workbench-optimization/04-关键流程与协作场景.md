# 04 关键流程与协作场景

> 本文只描述面板作为 Trellis 工作流可视化窗口的主路径。对应 [`02` 路线图](./02-产品优化方案与路线图.md) 与 [`03` 线框](./03-信息架构与页面线框图.md)。外部工具负责规划和推进，面板负责读取与定位材料。

## 图例

```text
用户：唯一使用面板的人
外部 Trellis 环境：Codex / Claude Code / CLI 等实际运行工作流的会话
项目文件：.trellis/tasks/、archive/、spec/、频道日志等
面板：扫描、展示、搜索、预览、打开原件
```

流程中的“观察到”表示面板从文件或明确外部响应读取到事实；不表示面板主动触发了该事件。

## 场景 A：外部讨论需求并创建任务

```text
用户                 外部 Trellis 环境             项目文件               面板
 │ 讨论需求与验收条件       │                         │                    │
 ├───────────────────────►│                         │                    │
 │ 确认规划结果            │                         │                    │
 ├───────────────────────►│ 按工作流建任务            │                    │
 │                        ├────────────────────────►│ task.json          │
 │                        │                         │ prd.md（若已写入）   │
 │                        │                         ├───────────────────►│ 扫描
 │                        │                         │                    │ 显示任务与现存材料
 │ 打开面板查看任务         │                         │                    │
 ├───────────────────────────────────────────────────────────────────►│
 │◄───────────────────────────────────────────────────────────────────┤ 阶段来源、文件清单
 │ 点“打开原件”            │                         │                    │
 ├───────────────────────────────────────────────────────────────────►│ 打开对应文件/目录
```

**边界**：面板不把待办素材自动当成正式任务，也不在此流程中创建 Trellis 任务。若新建任务只有 `task.json` 没有 `prd.md`，显示“未找到 PRD”；不显示“PRD 已生成”，也不自行替用户补造文件。

**失败路径**：扫描不到新任务时，显示最近扫描时间、项目根目录和重试入口；先核对外部工具实际写入的是不是当前项目，而不是给用户一个空白成功页。

## 场景 B：外部推进阶段，面板跟随变化

```text
外部 Trellis 环境                 项目文件                       面板
      │ task.py start / 实际会话推进  │                              │
      ├─────────────────────────────►│ task.json.status 更新        │
      │                              ├─────────────────────────────►│ 重新扫描
      │                              │                              │ 标签显示：进行中
      │                              │                              │ 注明“来自 task.json”
      │ 频道中可能出现 progress       │                              │
      ├─────────────────────────────►│ 频道日志（若存在）            │
      │                              ├─────────────────────────────►│ 独立显示原事件
      │                              │                              │ 不与任务阶段合成代理在线状态
```

**边界**：面板不会因为用户拖动卡片而触发 `start`，也不会根据 `in_progress` 推断“代理已经连续工作 42 分钟”。频道消息、任务阶段、Git/Jira 各保留自己的来源和时间。

**异常路径**：任务文件写入了一半或 JSON 无法解析时，页面保留上次可信快照并标“本次读取失败”；不可把旧阶段继续显示为实时阶段。

## 场景 C：查看实施与检查材料

```text
用户                         面板                              项目文件
 │ 搜索并进入目标任务           │                                   │
 ├───────────────────────────►│ 扫描材料清单                       │
 │                            ├──────────────────────────────────►│
 │                            │◄──────────────────────────────────┤ 文件、时间、读取结果
 │◄───────────────────────────┤ 按“需求/实施/检查/关联”显示        │
 │ 点 check-report.md（若存在）  │                                   │
 ├───────────────────────────►│ 预览原文，并保留打开原件入口        │
 │◄───────────────────────────┤                                   │
```

**三种情形**：

1. 文件存在且可读：预览内容，显示路径与文件时间。
2. 文件不存在：写“未找到”；没有项目规则支撑时，不推断代理没有检查。
3. 文件存在但读取失败：显示错误、上次成功读取时间与重试。

面板可以展示外部工作流已经生成的检查回执；当前不提供“重新派发检查代理”“检查通过后解禁归档”的主操作。

## 场景 D：外部归档，面板显示归档结果

```text
用户                 外部 Trellis 环境             项目文件                 面板
 │ 在外部确认收尾与归档    │                        │                      │
 ├──────────────────────►│ 执行项目实际归档流程     │                      │
 │                       ├───────────────────────►│ 任务移至归档目录       │
 │                       │                        ├─────────────────────►│ 扫描
 │                       │                        │                      │ 显示“已归档”及路径
 │ 打开归档材料            │                        │                      │
 ├────────────────────────────────────────────────────────────────────►│
```

**边界**：面板根据目录位置和读到的字段描述归档事实，不代替外部归档命令。若 `task.json.status=completed` 但目录仍在活动任务中，显示“状态记录为已完成，尚未扫描到归档”；不能自动帮用户移动目录或把两种情况画成同一状态。

## 场景 E：Jira 与频道信息不一致

```text
任务文件：status=in_progress，meta.jiraKey=ABC-123
Jira：读取到“待办”，读取时间 14:30
频道：最近一条 progress，记录时间 14:25

面板显示三条事实和各自来源 → 用户打开任务或 Jira 原件核对。
```

界面可以提示“本地任务阶段与 Jira 状态不同”，前提是两边都读到了有效数据；不自动判断哪边正确，也不从任务卡触发远端流转。Jira 不可达时写“远端状态暂不可读”，不把上次值涂成当前绿灯。

对账入口固定在 Jira 页“关联对账”视图（见 03 的 3.5 与 02 的 P0-5）：已挂钩任务↔工单并排显示两侧状态与读取时间；未关联工单提供“复制工单摘要”，把 key、标题、描述、链接递给外部 AI 会话作需求输入——面板递料，不再产生无人消费的待办文件。

## 主界面操作边界表

| 用户意图 | 本轮面板提供 | 实际工作流位置 |
| --- | --- | --- |
| 找任务与材料 | 搜索、筛选、预览、打开原件 | 面板 |
| 讨论需求、正式建任务 | 可查看已有任务/待办素材；不提供正式建任务主入口 | 外部 Trellis／AI 会话 |
| 启动、改阶段、确认完成 | 读取并标注来源；不提供拖拽与状态写入主入口 | 外部 Trellis 工作流 |
| 检查、修复、归档 | 查看已有记录和归档结果；不派发检查、不执行归档 | 外部 Trellis 工作流 |
| 阅读 Jira/频道 | 显示明确读到的记录与时间 | 面板；外部系统仍是各自事实来源 |
| 把 Jira 工单变成需求输入 | “复制工单摘要”一键复制（出口） | 外部 Trellis／AI 会话 |

## 可作为验收用例的失败路径

| # | 输入条件 | 正确表现 |
| --- | --- | --- |
| 1 | 当前项目没有任务 | 任务空态 + 项目路径；不提示“所有工作已完成” |
| 2 | `task.json` 损坏 | 显示读取失败、文件路径和重试；不复用旧阶段冒充当前值 |
| 3 | `prd.md` 不存在 | 显示未找到；不声称规划完成或自动生成 PRD |
| 4 | `check-report.md` 不存在 | 显示未找到/可能不适用；不自动判检查失败 |
| 5 | 任务 `completed` 但仍在活动目录 | 阶段与目录位置分别呈现，不叫“已归档” |
| 6 | 任务在归档目录但状态字段异常 | 显示目录事实与字段异常，保留原件入口 |
| 7 | 只有频道 `done` 消息 | 显示消息原文，不推断任务完成或归档 |
| 8 | 只有 `in_progress` 阶段 | 显示阶段，不宣称代理在线或给出运行时长 |
| 9 | Jira 读取失败 | 显示远端不可读/上次成功时间，不显示“已同步”绿灯 |
| 10 | 任务与 Jira 状态不同 | 并排显示两侧事实与时间，不自动推送 |
| 11 | 快照刷新失败 | 保留上次快照并加“可能过期”标记及重试 |
| 12 | 搜索筛选无命中 | 告知当前筛选无结果，提供清空筛选 |

以上流程只要求面板如实观察，不要求本轮接入 AI agent 平台。未来若要执行任务生命周期动作，应另写执行协议、权限、回执与失败恢复方案，再改动这些流程。
