# 05 产品评审与跨编辑器 Roadmap

> 日期：2026-09-29。
> 状态：**独立评审建议，待确认，不替代现行 00–04 文档中的已记录决策。**
> 评审对象：`09-29-workbench-visualization-proposal` 任务、现行五份方案、GLM 历史路线图及调研笔记。
> 方法：文档审阅、关键实现静态核对、开源项目一手资料研究。本轮未启动桌面应用，未进行真实用户测试，因此不提供虚构的 UI 评分、可用性测量或已验证兼容性承诺。
> 范围：产品与交互建议，不修改运行时代码，不创建/启动实施任务，不改写已有决策。

## 一、结论

**现行方案的产品边界基本合理，但还不能直接作为实施 roadmap。**

GLM 历史原稿把“看见任务”过早扩大为“指挥代理”，依赖尚未存在的事件、会话绑定与门禁协议。现行修订把任务生命周期留给外部 Trellis 工作流，这个方向应保留。但修订后的方案又偏向文件浏览器：阅读入口设计较多，跨编辑器的任务交接、项目身份、兼容性和启动失败处理较少。

建议定位为：

> **面向 Trellis 使用者的本地工作流伴随面板：看清任务与材料，带着正确上下文回到所选 AI 工具。**

主闭环：

**外部创建或推进任务 → 面板观察变化 → 阅读需求、计划与证据 → 选择工作环境并交接上下文 → 外部继续工作 → 面板重新读取。**

它应做到三件事：

1. **看得准**：任务记录、目录位置、材料、远端状态、运行事件分开表达。
2. **找得快**：任务是聚合阅读单元，材料可以直接阅读，不必连续打开弹窗。
3. **接得上**：跨平台共享任务事实与交接材料；只有具备适配器与会话证据的平台才显示“恢复会话”。

“无缝”的可验收定义是：**切换工具时不重建任务、不重抄路径、不丢已落盘的需求和决策、不会在错误 worktree 继续执行。** 不承诺把任意平台的聊天历史、隐藏推理、工具授权和运行状态迁移到另一个平台。

## 二、保留、修改与延期

### 2.1 应保留的决策

- 任务主路径不直接改 `task.json.status`，不通过移动目录冒充 Trellis 正式归档。
- 不从 `in_progress`、文件 mtime、频道 `done` 推断代理正在工作、检查通过或任务已经归档。
- 任务页面收敛为主从阅读布局，优先保留搜索、筛选、预览与外部入口。
- 最近快照读取失败时保留旧内容，并显示其时间与错误，不用空列表覆盖。
- `design.md`、`implement.md`、检查报告是否必需，取决于项目工作流与任务类型；不套用参考项目的定制规则。
- 停用后台 Jira 对任务阶段的直接回写，与隐藏前台状态按钮一起验收。
- 笔记、规范编辑等独立能力不因为“任务生命周期只读”被整批删除。

### 2.2 必须补齐的设计问题

| 问题 | 原文位置 | 为什么影响实际使用 | 建议修正 |
| --- | --- | --- | --- |
| 全局“当前任务”与会话级任务不一致 | `scan.ts:282-302、357-362` | 本仓 Trellis 已按会话记录当前任务，面板仍额外读取旧 `.current-task`；跨编辑器时可能显示错误焦点 | R0 区分用户当前查看的任务与各会话绑定的任务，不设置一个虚假的全项目唯一“执行中任务” |
| 接入请求跟随面板当前项目漂移 | `access/server.ts:126-141` | 外部客户端读取期间用户切换项目，会读到另一个 root；同名任务尤其危险 | 外部请求显式绑定 workspace；目标变化时拒绝或重新确认，不静默重定向 |
| 外部入口停留在打开目录、复制路径 | `03` §一、§3.3；`04` 操作边界表 | 用户仍需重新告诉 AI 当前任务、规范、实施计划和工作目录 | 将“复制任务交接包”和“在所选工具打开正确项目”纳入首个可用版本 |
| 把主从布局与删除独立详情路由捆绑 | `02` P0-1；`03` §3.2、撤下清单 | 从搜索、Jira、通知、外部链接进入任务会丢失稳定目的地；还容易形成一个更大的组件 | 页面外观收敛，但保留任务的稳定地址、选中状态、历史返回及可复用详情组件 |
| “材料 ✓✓”暗示材料齐备或检查通过 | `03` §3.2 | 文件存在不证明检查执行过，`check.jsonl` 是引用清单而非测试结果 | 默认行只展示事实型数量，例如“材料 3”；详情明确“已找到 / 未找到 / 无法读取”；不把文件存在画成通过对勾 |
| 正常来源说明与严重异常都依赖悬停 | `02` P0-2；`03` §3.2 | 键盘和触屏难以发现来源；过期数据可能被误读 | 正常来源放详情或可聚焦信息按钮，错误与过期直接可见；tooltip 同时支持 focus |
| 最近变化默认排序未定义数据基础与交互稳定性 | `02` P0-4；`03` §3.1、§3.2 | 目录 mtime 不一定随文件正文编辑变化；列表实时重排会移走正在阅读的任务 | 文件级指纹检测与观察时间分开；阅读时稳定选中行与视口，以“有新变化”提示用户主动刷新排序 |
| Jira 不同状态直接标“两边不一致” | `03` §3.5；`04` 场景 E | Jira 与 Trellis 是两套状态机，一个工单也可能对应多个任务；不同名称不等于冲突 | 默认并排显示，不报错；只有项目确认了状态映射、关联粒度且两侧数据新鲜时才提示“偏离约定映射” |
| 首页“资料体检”缺规则来源 | `02` P0-4；`03` §3.1 | 轻量任务、历史任务、不同版本可能合法缺某些材料，容易形成常驻假告警 | 分为“读取问题”和“材料提示”；仅对明确声明的要求做缺失警示，显示规则出处 |
| Jira 全页重构与核心阅读体验同列 P0 | `02` P0-5 | 对没有 Jira 的用户没有直接价值，却扩大首版范围 | 阶段回写停用仍属首批；完整关联对照页降为条件性连接器增量 |
| 既收敛任务主路径，又保留大量顶层执行入口 | `03` §二，AI 频道、定制中心、模型管理、MCP 等 | 用户仍分不清面板管理的运行与外部 AI 编辑器运行，定位没有落实到导航 | 把现有执行工具放到明确命名的可选扩展区，不冒充外部 Trellis 会话；不未经评估删除底层能力 |
| 将 worktree 基础识别与大型多仓管理一起延期 | `02` 远期探索 | 同一项目在不同 worktree 的任务和分支可能不同；跨编辑器首日就可能打开错误目录 | 单项目多 worktree 身份与路径在早期完成；多仓总览、容量统计仍延期 |

### 2.3 对历史 GLM 调研的判断

历史稿可作为想法池，不能作为可复用实现或成本估算依据。

- `research/oss-patterns.md` 明确说明没有逐一实测产品。Linear、Things 3、飞书也不是本次所需的开源实现依据。它们可以是交互参照，但要与开源代码、协议文档分开标注。
- “保存视图几十行”“底座全现成”“纯可视化升级”忽略了数据语义、错误恢复、工作区隔离和迁移，不能据此排期。
- 历史路线图对 Jira meta 的判断已被现行文档纠正，说明跨层事实必须查完整调用路径，而非只看 HTTP service。
- 借鉴成熟产品应说明四件事：解决什么问题、借哪个具体模式、依赖哪些数据、本项目明确不借什么。

## 三、产品范围与信息架构

### 3.1 用户与优先场景

先服务正在一个或多个 AI 工具里使用 Trellis 的开发者，默认本机仓库、单人使用。不先做团队考核、项目排期或代理资源调度。

按优先级覆盖四个场景：

1. **回到工作**：昨天做到哪里，应该先读什么，在当前工具中怎样继续。
2. **跨工具接续**：原工具额度、模型或环境不合适，换工具继续同一个已落盘任务。
3. **核对结果**：AI 声称完成，用户查 PRD、实施计划、检查材料、关联提交与归档位置。
4. **排查接入**：看不到任务、项目路径不对、worktree 不同、文件损坏或平台能力不足。

### 3.2 建议的默认导航

```text
项目切换器 [仓库 / worktree / 分支]

工作概览       最近查看、观察到的变化、读取问题
任务           活跃与归档共用实体和阅读组件
规范与知识     保留按实际目录组织的规范、笔记和资料
连接           AI 工具、本地环境、可选 Jira / GitLab

更多工具       现有 AI 频道、面板内 Flow、架构工具等独立能力
设置           外观、快捷键、读取策略、隐私与日志

全局搜索       页面 / 任务 / 规范 / 已索引材料
```

这是新增建议，不声称四组导航已经批准修改。首批允许保留现有导航容器，先调整默认可见项和命名，不做全站推倒重来。

归档保留为明确的筛选视图，旧归档地址继续可达；不把知识文档和归档任务混成同一种对象。“待办池”可保留为需求素材入口，能复制给外部 AI，但不再暗示点击即可正式建任务。

### 3.3 首页应把“继续阅读”放在“变化流”前

首屏依次显示：

1. **最近查看 / 手动置顶的任务**：本地偏好，不是工作流优先级，不写回任务。
2. **观察到的变化**：任务字段变化、材料新增或内容变化；无历史时只显示当前材料及文件时间。
3. **读取问题**：只有存在问题时占明显位置，行内提供重试和原件入口。

统计只做轻量过滤入口。不给一个没有任务的仓库显示“完成率 100%”。也不因为三天没有文件变化就称任务停滞。

## 四、任务页面与关键交互

### 4.1 主从布局

```text
项目 A / worktree feature-x                搜索             连接状态

任务                      登录超时修复
搜索与筛选                记录阶段：进行中   位置：活跃任务
                          [复制交接包] [在 Cursor 打开 ▾] [更多]
登录超时修复  进行中
材料 3 · 观察于 14:32      概况 | 材料 | 变化 | 关联

规范索引更新  规划中       需求  prd.md        正文直接阅读
材料 2 · 观察于 13:10      设计  design.md     当前选中文件、来源和时间
                          实施  implement.md  可打开原件、复制路径
数据导入修复  未知阶段
无法读取 task.json        无法读取的材料保留行并解释原因

活跃 / 已归档             原始字段与上下文引用放在可展开区域
```

线框是建议交互，不是运行截图；工具名称只表示用户选择的适配器示例。

### 4.2 详情不是另一层文件管理器

- “概况”展示任务标题、记录阶段、位置、PRD 中可定位的目标与验收章节、关联材料入口。章节无法可靠定位时直接展示原文，不生成假结构。
- “材料”默认直接阅读 PRD，点击设计、实施或其他材料时替换正文区域。文件多时再展开轻量文件列表，不固定占用第三个宽栏。
- “变化”只显示实际观察到的差异与时间。不把 Git 历史、文件时间和代理事件拼成一条看似完整的执行审计链。
- “关联”展示分支、worktree、工单、显式会话绑定及各自来源。不存在的关联不凭标题相似度自动补齐。
- `implement.jsonl/check.jsonl` 表述为“配置的上下文引用”，不是“AI 已读取的规范”。是否真正注入或读取需要另一种回执。
- 自动摘要如未来启用，必须标为辅助摘要、可回到引用原文；不作为 P0 依赖。

### 4.3 布局、键盘与恢复

- 宽窗口采用可调整的列表与详情；列表建议初始宽度 280–340 CSS px，正文剩余宽度优先，最终由真实内容与缩放测试修订。
- 小于约 960 CSS px 的窗口进入列表或全宽详情，用明确返回入口，不用多层覆盖抽屉。旧地址、当前筛选和滚动位置可恢复。
- 以 `/tasks/<task-key>` 或等价的应用导航状态表达选中任务，不要求为了实现主从界面引入新的大型路由框架。
- 列表获取焦点时方向键导航；Enter 查看；搜索框输入及中文 IME composition 时不触发列表快捷键。`/` 只在非输入控件内聚焦搜索；Ctrl/Cmd+K 沿用全局搜索。
- 不把“双击打开系统目录”设为唯一快捷路径。文件原件操作使用可见按钮或菜单；双击最多是可关闭的附加操作。
- 阅读期间不自动跳任务、不抢焦点、不因后台刷新重置当前材料、展开状态或滚动位置。
- 长标题两行封顶或提供完整可访问名称；路径可选中复制；重要状态必须有文字，不依赖颜色、小点或悬停。

### 4.4 保留视觉体系，降低装饰密度

现有 `src/renderer/src/styles.css` 已有 ink/mist 中性色与 leaf 绿色，并具备浅/深主题。建议沿用，而不是引入新的“AI 控制台”皮肤。

- 列表和详情以分隔、对齐和留白组织，避免每份材料再包一层卡片。
- 正文建议 14px 起、约 1.6 行高；任务标题约 18–20px；元信息 12–13px。实际 Windows 125%/150% 缩放下检查，不将这些数值当成未经验证的定稿。
- 绿色用于选中或明确成功动作，不表示“文件存在所以任务通过”。错误、过期、未知各有文字。
- 普通文本和控件标签按 WCAG AA 对比度目标验证；引用原文和路径可选中；焦点环、键盘操作、减少动态效果一并验收。
- 仅保留短暂状态过渡，不使用代理工作动效或无依据的实时呼吸灯。

## 五、跨编辑器接入设计

### 5.1 把能力拆开，不能用一个“已连接”遮盖

| 能力 | 用户得到什么 | 需要什么 | 不能由此宣称什么 |
| --- | --- | --- | --- |
| 读取项目 | 面板看到同一份任务、规范和材料 | 受信任项目路径、兼容 reader | AI 会话已连接 |
| 打开项目/文件 | 在所选工具打开正确 worktree 与材料 | 受支持的 URL/CLI 适配器、已配置目标 | 原聊天已恢复或任务已接手 |
| 交接上下文 | 新会话知道要先读哪些资料、核对什么 | 可复制交接包，后续可选只读 API | 历史聊天、授权已迁移 |
| 观测会话 | 看见特定会话最后报告的事件 | 明确的绑定、结构化事件、失联规则 | 任意平台都能实时监控 |
| 恢复会话 | 回到某个平台保存的会话 | 该平台真实支持的 resume/load 与有效会话标识 | 别的平台可导入其私有会话 |
| 执行/批准动作 | 启动代理、回复权限请求或推进工作流 | 新的产品授权边界、权限、回执、失败恢复 | 属于本轮只读面板的默认能力 |

前面三个能力组成首个跨工具闭环；观测、恢复分别增量提供；执行是另一项产品决策。

### 5.2 所有平台共享的最小交接包

首版不依赖 LLM 生成，不复制整仓库，不复制凭据或完整聊天记录。通过已有文件生成可预览、可编辑、可复制的文本：

```text
任务：<标题与任务标识>
工作目录：<本机选定 worktree 的绝对路径>
任务目录：<相对工作目录的任务路径>
记录阶段：<原值>，读取于 <时间>

请先核对工作目录，再读取：
1. 项目入口说明（实际存在的 AGENTS.md / 对应平台说明）
2. .trellis/workflow.md
3. 当前任务 prd.md
4. 当前任务 design.md / implement.md（存在时）
5. implement.jsonl / check.jsonl 所列引用（按本项目流程与当前阶段）

本次用户意图：<例如：审阅计划，不开始实施>
已知读取问题：<缺失/无法读取/无>
请通过当前平台的 Trellis 流程确认并绑定任务。
不要因为复制了这份交接材料就创建重复任务、自动开始实施或归档。
```

“本次用户意图”首版留作用户选择或输入，默认只核对与阅读。不凭任务阶段生成“现在开始编码”的隐含授权。

剪贴板中默认只有索引和必要元信息。若用户要带 PRD 原文、Jira 描述或片段，应先展示将离开本地工具的内容。粘贴给外部模型是用户的显式动作；未来自动发送需要独立确认。

本地路径用于当前机器；跨设备时重新绑定本机项目，不能把另一台机器的绝对路径当可执行位置。

### 5.3 正确的打开流程与反馈

1. 用户点“在所选工具打开”。首次选择平台与本机可执行文件或受支持的 URL scheme。
2. 面板列出目标项目、worktree、分支和准备打开的文件；初次或目标变化时确认。
3. 适配器尝试打开项目；可复制交接包一直作为独立可用操作。
4. 无接收方回执时只显示“已发送打开请求”，不要显示“已连接代理”。
5. 工具不存在、scheme 不支持、进程启动失败时保留材料和当前阅读状态，提供复制路径、重新选择工具等回退。
6. 只有适配器确认原平台支持加载且定位到有效会话，才另外出现“恢复此会话”。

连接页按能力显示“可读取 / 可打开 / 可取上下文 / 可观测 / 可恢复”，分别标明未配置、不支持、不可达，不能只有统一绿色在线灯。磁盘上有 `.cursor/` 或 `.claude/` 只证明存在配置材料，不证明软件已安装或会话在运行。

### 5.4 架构边界

**增量整理现有能力，不新建一套平行基础设施。** 当前已经有 `handoffTexts`、`TaskWorkspace`、独立知识 MCP、TPAP 本地 HTTP 访问和深链/文件 inbox 桥。它们分别负责不同方向，目前尚未形成完整接续合同。建议保留有用实现，统一读取、身份与结果语义。

- **Trellis reader**：解析文件、目录位置、来源、新鲜度与兼容性；供桌面 UI 和可选 headless bridge 共用。原始任务数据仍是事实来源，索引可删除重建。
- **交接包构建器**：改造现有 `handoffTexts`，接受明确任务身份和用户意图，生成确定性文本及材料索引；不承担规划或自动执行。去掉硬编码的“自动加载技能”“直接更新 task.json”承诺，按实际版本给指引。
- **环境打开适配器**：每个平台只声明实际支持的打开方式；使用结构化参数，不把路径或任务标题拼成 shell 命令。
- **只读上下文接口**：在已有独立知识 MCP 与 TPAP 之上扩展任务材料读取，避免新造同义协议。现有内部网关的工具目录、知识 MCP stdio 服务、TPAP HTTP 服务不是同一回事；TPAP 也不是 ACP。将任务、设计、实施与上下文引用交给支持 MCP 的客户端，应共享 reader 并显式绑定工作区，不能直接复制当前只读 task.json + PRD 的接口就宣称完整接入。
- **可选事件接入**：复用现有深链/文件 inbox 的传递能力，优先消费平台官方支持的 hook、插件事件或明确回执，不读取私有聊天数据库、不抓 UI 文本推断进度。现有生命周期 `task-event` 可触发刷新，但不足以证明会话正在运行或等待输入。
- **ACP**：可用于支持该协议的 client–agent 交互，但不是所有编辑器的通用遥控器，也不能取代 Trellis 的任务事实。如果让面板成为 ACP client 来启动/驱动 agent，已经进入执行产品范围，应另行决策。

不要让只想读取本地任务的用户必须配置模型 API key、启动网关或保持桌面面板常开。若引入 headless bridge，应与 UI 共用 reader，并能独立运行；首版纯文件方案不依赖它。

### 5.5 工作区身份与兼容性

- 从最早的 reader 开始区分仓库、工作树、任务。运行时定位不能只用任务标题或目录 basename；至少包含规范化 worktree 根路径与任务相对路径，另维护归档/移动时的映射。
- 如上游任务本身有稳定 ID，应保留并与工作区共同使用；不能假定同名任务在不同 clone、worktree 中是同一个执行上下文。
- Windows 大小写、盘符、空格、中文、符号链接与 `.git` 文件式 worktree 要有测试。WSL/SSH/远端只在路径映射与打开方式验证后开启，不简单替换斜杠就称兼容。
- 读未知字段不丢弃，未知状态显示原值；未识别版本保守只读，而不是自动写成默认阶段。
- 本仓 `.trellis/.version` 为 `0.6.17`。公开 upstream 与本地安装、定制脚本不能仅凭同一版本标签视为完全一致；用本仓、旧结构和未识别结构夹具分别验证。会话文件中的 `last_seen_at` 不是持续心跳，界面应写“最后记录”，不能直接写“在线”。
- 用户当前阅读任务与外部会话绑定任务分开。多会话是多条绑定；不继续把旧 `.current-task` 当项目级唯一焦点。
- 现有知识 MCP 安装会写项目配置和用户级配置。新连接设置必须先显示目标文件与 diff，按工具逐项启用；解析失败时停止、不用空对象覆盖原配置；已有 server key 冲突与项目 root 变化需确认；提供备份与卸载回滚。不因用户添加一个工具就自动改其他平台配置。
- 不将面板偏好、接收日志、会话临时状态塞进任务权威字段。默认用面板本地存储；新增仓库共享协议须版本化并另行确认。
- 读取原文时允许渲染安全 Markdown，不执行文档脚本、hook 或自动生成命令。首个读取动作不自动运行仓库程序。

## 六、按依赖交付的 Roadmap

以下时长是**单名熟悉项目的开发者、有 AI 辅助且能连续投入**的初步范围估计，不是承诺；包括基本自动测试和 Windows 冒烟，不包括全平台发布认证。每阶段放行看验收，不看日历。新增平台的成本应在两个试点后重新估算。

| 阶段 | 建议投入 | 交付内容 | 对用户的结果 | 放行条件 |
| --- | --- | --- | --- | --- |
| R0 可信数据与边界 | 3–5 工作日 | 入口审计；停止任务主路径和 Jira 后台越权写阶段；读错误/未知状态/归档/材料模型；项目和 worktree 标识；测试夹具 | 面板不会把未知当正常，也不会悄悄改变任务 | 通过读坏文件、未知阶段、归档差异、后台静默写入检查 |
| R1 日用阅读与基础交接 | 5–8 工作日 | 主从任务页、稳定任务地址、直接读材料、搜索、首页最近查看/变化、复制交接包、打开原件 | 找到任务、读懂上下文并交给任何可粘贴文本的工具 | 典型任务两步内读到 PRD/计划；新会话靠交接包定位正确任务，不需重新建任务 |
| R2 两个平台的工作环境适配 | 5–8 工作日 | 能力式连接页、打开项目/文件适配、路径校验、失败回退；一组 CLI 场景和一组 GUI 编辑器场景 | 开对目录、带对资料，不再手动拼路径 | Windows 中文/空格路径、两个 worktree、未安装工具、过期绑定均通过；启动请求与恢复会话不混用 |
| R3 可选只读桥接与轻量会话观测 | 8–12 工作日，按需 | 独立只读上下文 bridge；有需求的平台接入结构化事件；来源绑定、失联与去重；支持者才加同平台会话恢复 | 少复制材料；在有证据的平台看到会话状态 | 两个客户端得到一致任务索引；重复/乱序/断联不造成假完成；只读接口不能改阶段 |
| R4 按使用证据扩展 | 逐项 3–8 工作日评估 | Jira 关联对照、更多平台、规范引用优化、历史检索、多项目阅读 | 解决已经观察到的高频问题 | 每项有使用场景、维护负责人、兼容夹具与独立验收 |

**R0 → R1 → R2 是首轮产品交付。R3 不是启动产品的前置条件。** 如果资源紧张，先交付 R0+R1：即使用户的 AI 工具没有任何插件或协议支持，仍可通过共享文件与交接包获益。

### 6.1 各阶段的关键取舍

**R0：先去掉错误权力，再优化外观。**

- 盘点所有任务写入口，包括命令面板、规划弹窗、Jira/待办转换、详情编辑、DoD、归档及后台定时器。
- 修正旧全局当前任务读取，保留实际会话绑定；为现有本地访问接口加入显式工作区绑定或失配拒绝，避免“UI 切项目导致外部请求换仓”。
- 文件级 mtime/size 与 watcher 已存在，应增量建立变化观察，不重建文件监听服务。现有 activity 历史缺项目标识，不能原样升级成多项目权威历史。
- 不要求第一批删除所有底层 API；明确区分要停用的生命周期行为、仍有独立价值的元数据编辑、现有执行扩展。
- 不把“关联 Jira”当纯读操作。若保留元数据写入，要防止它用旧快照覆盖外部刚更新的阶段和未知字段；无并发保护时先退到只读或确认后重读。

**R1：用最小闭环证明面板值得每天打开。**

- 先交付确定性的材料索引和交接包，暂不增加 AI 生成摘要。
- 保存最近查看、选择和滚动位置；先不做任意字段查询语言、十种保存视图或大而全的知识搜索。
- 文件变化以面板实际观察为边界，首次扫描不是历史事件回放。

**R2：验证两条真实环境链路，而不是列十个支持 Logo。**

- 默认优先覆盖文档已有的 Claude Code / Codex 使用场景，再选择 VS Code 或 Cursor 的 GUI 打开场景；这是建议次序，最终以实际常用环境调整。
- “CLI 运行在某编辑器终端里”和“编辑器原生 AI 扩展”不是同一个适配对象。验收时写明宿主、agent、插件与版本组合。
- 通用复制始终兜底；不支持恢复的工具照样可以支持同任务的新会话接续。

**R3：让真实事件增加能力，而不是倒过来用 UI 倒逼虚构数据。**

- bridge 的建议最小读能力是：列任务、取任务上下文、取受限材料。接口名与协议待正式设计，不是现有 API。
- 事件至少带来源、项目/worktree、任务、会话、事件 ID、报告时间与接收时间；并明确有效期、去重、重放、结束与断联语义。
- 收到 `turn_end` 只表示一轮交互结束；收到 `task_finished` 也须标明谁报告，不能替代目录归档或权威工作流记录。
- 展示权限请求时只引导回原工具处理；在面板内批准权限或直接发送回复需要额外的执行授权设计。

### 6.2 不进入当前承诺的功能

- 通用多代理调度器、面板自己的任务状态机、面板统一所有 AI 工具授权。
- 面板驱动的 Jira 双向自动流转，以及未配置映射就展示同步冲突。
- 无证据的“等我处理”“代理负载”“停滞时间”“健康评分”和吞吐趋势。
- 跨平台完整聊天历史迁移、静默恢复会话、在用户不知情时接管任务。
- 要求所有项目迁移规范目录、增加强制 `check-report.md`，或为面板改写上游 Trellis 工作流。
- 甘特图、审批流、通用终端、独立交付物平台和企业报表。

## 七、验收与验证计划

### 7.1 第一轮必须覆盖的测试材料

| 样本/场景 | 预期结果 |
| --- | --- |
| 轻量任务，只有 task.json 和 PRD | 正常可读，不因缺设计文件显示失败 |
| 复杂任务，有 design/implement/jsonl | 可直接读正文与引用；不宣称引用已执行注入 |
| JSON 写入一半、损坏或权限拒绝 | 任务不静默消失；显示本次错误和上次成功时间 |
| 自定义状态和额外 meta | 原值可见，读取不丢字段、不改成 planning |
| `completed` 在活动目录；归档目录中字段异常 | 记录阶段与位置分开，不给虚假通过标记 |
| 仅编辑已有 PRD 正文 | 能被文件级检测观察到；不依赖目录 mtime |
| 外部归档/重命名发生在当前阅读期间 | 选中对象能重新定位或提示位置变化，不切到另一条同名任务 |
| 一个工单关联多个任务、状态名称不同 | 并排展示；未设映射不报冲突 |
| 同仓两个 worktree 存在同名任务 | 打开的工作目录和任务都与用户所选上下文一致 |
| 中文、空格、含 shell 特殊字符的合法路径 | 参数不会被当命令解释，材料可定位 |
| 工具未安装、深链不支持、会话已失效 | 不假报成功；交接包与复制路径仍可用 |
| 在任务里明确只要求审阅、不开始实施 | 交接包保留该意图，不暗中变为启动指令 |
| 背景刷新、读材料、搜索和中文输入并发 | 焦点与选中任务稳定，不发生误触快捷操作 |
| 深浅主题、键盘、Windows 125%/150% 缩放 | 主要信息不截断，错误可见，所有主操作可用键盘完成 |

R3 再增加事件重复、乱序、断联、回执超时与两个 MCP 客户端的只读契约测试。远程与 WSL 不通过相应夹具前标为未验证，不列正式支持。

### 7.2 产品目标，不能冒充已测数据

建议先选 5–10 个真实任务，记录当前基线，再以相同任务进行改版对照：

- 从进入任务页到找到指定 PRD/实施计划的时间，目标多数场景不超过 10 秒。
- 主路径寻找材料的导航操作，目标不超过两次；纯滚动和键盘搜索另记录。
- 同机切换到另一个工具并定位同一任务，目标 30 秒内完成交接操作；不把模型响应速度计入 UI 保证。
- 受支持本机文件变化在闲置 UI 中可见，初步目标 2 秒左右；需区分防抖、完整写入等待、网络盘与大仓条件。
- 错误成功提示、错误 worktree 打开、任务生命周期静默写入：测试样本中为零。

不将用户 PRD、源代码、交接文本或 Jira 描述上传为遥测。首轮可用人工计时和本地匿名动作计数，不先建分析服务。

## 八、建议如何回写现行任务

用户确认后再回写，不以本报告覆盖既有决定：

1. `00`：补“跨工具任务交接”的价值陈述，保留任务生命周期外部负责。
2. `01`：新增工作区身份、实际跨工具出口、reader 容错和桥接方向四项差距，按代码证据更新现状。
3. `02`：将 P0/P1 改为 R0–R4 依赖路线；Jira 回写停用提前，对照页降为条件性扩展。
4. `03`：保留稳定详情目的地；材料默认直接阅读；增加连接能力状态和交接包预览；修正文案、键盘及窄窗交互。
5. `04`：补首次接入、跨工具接续、错 worktree、工具不可达、会话不能恢复、用户只授权审阅等流程。
6. 对任务 `prd/design/implement` 的修改及后续实施子任务另经确认；不因本轮评审自动启动实现。

| **Trellis** | 官方多平台文档以共同 `.trellis/` 为核心，各平台 hooks、commands、skills、subagents 不同；本轮上游 CLI package.json 为 0.6.17 | reader 统一，平台差异放适配器；以任务材料作为可移植上下文 | 不把一个平台的 slash 命令硬编码给所有平台，不将上游 main 等同于 npm 最新版或本机实际能力 |
| **Agent Client Protocol / Zed 生态** | `initialize` 协商能力；`session/load` 依赖 `loadSession`，需要正确的 sessionId/cwd 等；当前正式会话文档还区分可选 `session/resume` 与历史回放 | 按能力呈现操作；明确“不支持恢复”的回退 | 不把 ACP 当成所有现有 IDE 会话的附着接口或跨 agent 聊天迁移格式 |
| **Model Context Protocol** | host/client/server 提供 resources、tools、prompts；协议聚焦上下文交换，不规定宿主怎样管理模型与会话 | 复用知识 MCP，按需读取任务、规范、材料；只读查询也可以是 tools | 不把安装 MCP 称为拿到宿主会话控制权，不把工具目录状态当外部连接状态 |
| **Vibe Kanban** | README 展示任务与 agent workspace、分支/终端、diff review、inline comments、打开编辑器等链路；本轮 README 原文为 “Vibe Kanban is sunsetting.” | 借任务与工作副本绑定、材料/diff/外部入口跟随同一任务切换；审阅意见可复制交接 | 不引入其进程调度、自动 worktree 或 merge 假设；不作为新项目长期运行时依赖 |
| **Continue** | README 描述 CLI、VS Code、JetBrains 多宿主入口；本轮 README 自述不再积极维护、仓库只读，并标示最终 2.0.0 | 借“共享核心能力、宿主薄适配器”的思路 | 不声称多宿主等于聊天互通；不把停维项目作为接入底座 |

维护状态是上述项目 README 在检索时的声明，不是本轮通过 GitHub API 确认的 `archived` 字段；停止维护也不意味着原许可证自动失效。Trellis 本轮上游 CLI package.json 标为 `AGPL-3.0-only`，如引入/分发源码而非只参考交互，应单独检查许可证义务。
