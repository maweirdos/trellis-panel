# 03 信息架构与页面线框图

> 当前有效交互方案；与 [`02`](./02-产品优化方案与路线图.md) 的 P0/P1 对齐。以下是目标界面线框，**不是已实现截图**。2026-09-29 二次修订：任务页改为主从布局、概览改入口页、Jira 增加对账视图。

## 一、设计原则与术语

1. **先给事实，再给解释。** 阶段、归档、Jira 和频道分别标来源；摘要能点开原件。
2. **任务主界面只读生命周期，单一主从布局。** 不提供拖拽改阶段、状态下拉、确认完成、归档、任务派发或“AI 规划成正式任务”的主按钮；看板/泳道/阅读多布局收敛为“左列表 + 右详情”一种。
3. **三种空态分开写。** “未找到文件”“尚未收到事件”“读取失败”不是一回事，也不能统一画成绿色对勾。
4. **保留现有视觉体系。** 沿用当前主题与卡片样式；状态由文字与图标共同表达，颜色仅辅助。
5. **外部继续工作有明确出口。** 打开任务目录、打开原始文件、复制路径；在不知道外部会话地址时，不展示虚构的“继续执行”按钮。

| 界面词 | 含义 | 避免的说法 |
| --- | --- | --- |
| 任务阶段 | `task.json.status` 当前读取值 | 代理状态、执行进度 |
| 已归档 | 任务位于扫描到的归档目录 | 自动等同于“所有检查通过” |
| 频道事件 | 某频道确实记录的一条消息/事件 | 自动认定为“等待我处理” |
| 待办池 | 需求素材列表 | Trellis 正式任务列表 |
| 最近扫描 | 面板读取项目的时间 | 代理最后工作时间 |

## 二、目标信息架构

沿用现有四组导航，不以本轮方案增加“指挥中心”“通知中心”“交付物中心”等一级页面。P0 调整概览、任务页以及跨页正式建任务入口的主路径；P1 改善查找能力。

```text
trellis-panel
├─ 工作台
│  ├─ 项目概览（原“概览”；项目快照、读取状态、任务入口）       P0-4
│  ├─ 待办池（需求素材；与正式任务明确区分）                现有页，文案校正
│  └─ 任务（主从布局：列表 + 详情；只读任务阶段）            P0-1、P0-2、P0-3
├─ 知识
│  ├─ 知识库
│  ├─ 规范文档
│  └─ 归档（只读）
├─ 协作与连接
│  ├─ AI 频道（现有派发台与记录展示；其任务派发边界另立评估，不由本方案一刀切）
│  ├─ 团队协作（统计与报告须标明数据来源）
│  └─ Jira 任务（工单浏览 + 关联对账，见 02 P0-5）
└─ 系统
   ├─ 架构图 / 定制中心 / 模型管理 / MCP 网关 / 设置
   └─ AI 对话：P1 评估可见入口，不能当作 Trellis 任务规划主路径

全局查找：页面 + 正式任务 + 待办素材 + 归档；搜索结果标类别。
```

“看板”一词在目标设计中不再使用：任务页收敛为单一主从布局（见 3.2）。现有代码仍允许拖拽与多布局，本节是后续改造目标。

## 三、P0 关键线框

### 3.1 项目概览：变了什么、坏了什么、从哪继续

```text
┌─ 项目概览 ──────────────────────────────────────────────────────────┐
│ 扫描于 09-29 14:32 · 读取正常 · 来源 D:\...\.trellis                │
│ [重新扫描] [打开项目目录]                                          │
├───────────────────────────────────────────────────────────────────┤
│ 最近在动的任务（点行直达详情）                                     │
│  09-29 14:10  规范索引修正 · 文件有更新            [查看详情]       │
│  09-29 09:32  登录修复 · 新增检查材料              [查看详情]       │
├───────────────────────────────────────────────────────────────────┤
│ 资料体检                                                           │
│  ⚠ 2 个任务文件读取失败 · 1 个任务缺少 prd.md       [查看明细]      │
├───────────────────────────────────────────────────────────────────┤
│ 阶段计数（一行）：规划中 5 · 进行中 3 · 评审中 2 · 已归档 28        │
│ （计数来自 task.json，仅说明记录值，不代表代理正在运行）            │
└───────────────────────────────────────────────────────────────────┘
```

概览是入口页，不再是统计仪表盘：主体只放“最近变化流”和“资料体检”两块可点内容，计数压缩为一行。顶部固定显示扫描时间与项目路径；扫描失败时保留上一份可读快照并整页标注“数据可能已过期”与失败原因。变化流只有目录 mtime、无法确认具体文件时写“任务目录发生变化”，不写“代理刚完成检查”。

### 3.2 任务页：主从布局（左列表，右详情）

```text
┌─ 任务 ─────────────────────────────────────────────────────────────┐
│ 🔍 搜索标题/目录  阶段▾  优先级▾  材料▾  排序:最近变化▾  扫描于14:32 │
├──────────────────────┬──────────────────────────────────────────────┤
│ 任务列表（左栏）      │ 详情（右栏，内容见 3.3）                     │
│                      │                                              │
│ ▸ 规范索引修正       │  ┌─ 登录修复 ─────────────────────┐         │
│   进行中·09-29·✓✓   │  │ 09-29-login-fix · 规划中〔task.json〕     │
│   登录修复           │  │ [打开任务目录] [复制路径]        │         │
│   规划中·09-29·✓—   │  │ …材料清单（见 3.3）…            │         │
│   数据校验           │  └────────────────────────────────┘         │
│   评审中·09-28·——   │                                              │
│   ⚠ 未知任务(读取失败)│                                              │
│   （共 11 个）       │                                              │
└──────────────────────┴──────────────────────────────────────────────┘
```

- 只保留这一种布局；看板、泳道、阅读模式与拖拽全部删除，Tasks 与 TaskDetail 两个页面合并实现。
- 列表行只放标题、阶段标签、日期与材料圆点（✓✓ 表示 PRD/检查材料齐备，悬停展开明细），**不放解释句子**；阶段标签后的小标记 `task.json` 悬停才出完整说明。
- 交互：点行右栏即时切换；键盘 ↑↓ 换任务、`/` 聚焦搜索、双击行打开任务目录；窄窗口右栏转覆盖式抽屉。
- 阶段是筛选项不是操作目标：列表默认按“最近变化”排序，比看板更适合回答“最近什么在动”。

### 3.3 任务详情（任务页右栏）：材料清单与原件并重

```text
┌─ 登录修复 ─────────────────────────────────────────────────────────┐
│ 09-29-login-fix    阶段：规划中〔来自 task.json〕                 │
│ 任务目录：D:\...\.trellis\tasks\09-29-login-fix                │
│ [打开任务目录] [复制路径]             记录读取于 14:32            │
├─ 需求与计划 ──────────────────────────────────────────────────────┤
│ ✓ prd.md          修改于 09-29 13:50     [预览] [打开原件]         │
│ — design.md       未找到；此任务可能无需该文件                    │
│ — implement.md    未找到；尚不能从缺失推断流程违规                │
├─ 实施与检查 ──────────────────────────────────────────────────────┤
│ ✓ implement.jsonl  2 条规范引用      [查看引用与理由]             │
│ — check-report.md 未找到；当前工作流未必生成此文件                │
├─ 关联与位置 ──────────────────────────────────────────────────────┤
│ Jira：ABC-123〔来自 task.json.meta〕 [打开工单]                   │
│ Git 分支：codex/login-fix〔来自 task.json〕                       │
│ 归档位置：未扫描到此任务的归档目录                                │
└───────────────────────────────────────────────────────────────────┘
```

文件清单不强行把每份任务都套进同一检查模板。仅对项目明确要求的文件才使用“应有而缺失”的警示；其他文件写“未找到/可能不适用”。引用、预览、原件采用同一个路径，摘要旁能检查证据。现有详情中的写入控件要退出主阅读区，而不是换个图标继续保留。

### 3.4 缺失、错误和过期态

```text
未找到文件：  “未找到 prd.md。此任务可能还在规划中。” [打开任务目录]
读取失败：    “task.json 无法解析；上次成功读取于 13:10。” [查看错误] [重试]
扫描过期：    “项目自 14:32 后未成功刷新；以下是上次快照。” [重新扫描]
无频道数据：  “没有可读取的频道记录，无法判断代理活动。” [打开频道页]
筛选无结果：  “没有符合当前条件的任务。” [清空筛选]
```

禁止把“无数据”写成“没有等你处理的事”。错误态不只靠红色；文字说明、时间和下一步都要有。

### 3.5 Jira 关联对账（见 02 P0-5）

```text
┌─ Jira 任务 ─────────────────────────────────────────────────┐
│ [工单列表] [关联对账]                远端读取于 14:30 [刷新]  │
├─ 关联对账 ───────────────────────────────────────────────────┤
│ 任务              本地阶段    Jira 状态                       │
│ 09-29-登录修复    进行中      待办      ⚠ 两边不一致          │
│   ABC-123 [打开工单][打开任务]   本地14:32 / 远端14:30        │
│ 09-28-规范修正    已完成      完成      ✓                     │
├─ 未关联的工单 ───────────────────────────────────────────────┤
│ ABC-131 修复超时   待办   [复制工单摘要]  [关联到任务 ▾]      │
└──────────────────────────────────────────────────────────────┘
```

对账只标注不一致，不推送任何一侧。“复制工单摘要”把 key、标题、描述、链接复制到剪贴板，供外部 AI 会话作需求输入。“加入待办池”与“AI 规划”入口撤下。

## 四、P1 局部优化

### 4.1 全局查找

命令面板结果分“页面 / 正式任务 / 待办素材 / 归档 / 规范”组，统一名称。任务命中显示目录与记录阶段；归档命中显示位置。动作组以导航、复制路径、打开原件等阅读动作优先。AI 对话入口可补可见性，但不命名为“开始 Trellis 规划”。

### 4.2 本地阅读视图

```text
当前筛选：阶段=评审中 · 有检查材料      排序=最近文件变化
[保存为本地视图] [重置]
```

保存的是面板阅读设置，不写任务文件；“按代理”筛选须等稳定关联建立后再出现。视图名称不能与工作流阶段名称混淆。

### 4.3 Jira、频道、规范

- Jira 读取体验在 3.5 对账视图基础上优化（缓存、错误态、字段密度）；冲突展示差异、不自动推送的原则不变。
- 频道动态按原始事件时间展示；大量同类 progress 可以折叠，但不能从自由文本推断“必须回复”。
- 规范页强化目录、索引与引用导航；不对没有参考项目三轨结构的仓库显示空的 `rules/business` 页。

## 五、从主界面撤下的操作

| 现有/旧方案入口 | 目标处理 |
| --- | --- |
| 看板拖拽改阶段、详情状态下拉 | 从任务主界面撤下；阶段改为只读标签 |
| DoD 确认完成、面板直接归档 | 从任务主界面撤下；保留查看已完成记录和归档材料 |
| AI 规划后直接“创建 Trellis 任务”、Jira/待办转正式任务 | 不作为当前主路径；待办素材与正式任务明确区分 |
| 命令面板“派发/运行命令/改阶段”类动作 | 不随本轮阅读优化扩容；未来 agent 平台立项时再设计 |
| 看板/泳道/阅读多布局、独立任务详情页 | 收敛为单一主从布局；Tasks 与 TaskDetail 合并为一个页面 |
| Jira“加入待办池”“AI 规划”入口 | 撤下；换成“复制工单摘要”出口与“关联到已有任务”（见 02 P0-5） |
| 后台 Jira→task.json 状态自动回写（autoSyncJira） | 停用或删除；任务阶段权威在外部工作流 |

本表是**后续代码改造清单**。现有产品尚未按表移除。底层 IPC 的处置、旧入口兼容和独立工具页影响须在实施任务中逐项确认。
