# 02 产品优化方案与路线图

> 当前有效路线图。前置事实见 [`01`](./01-现状盘点与差距分析.md)。本文件描述后续产品实施方向，**本次只修改文档，没有修改应用**。2026-09-29 二次修订：任务页重构为主从布局、概览入口化、Jira 页对账化；方向已记录，细节仍可迭代。

## 目标与衡量方式

让用户打开面板后，快速回答“任务文件记录了什么、有哪些材料、资料从哪里来、要去哪里继续工作”。面板的价值由**找资料的效率和事实表达的准确性**衡量，不由它能替用户点击多少 Trellis 流程按钮衡量。

验收应以真实任务样本检查：从首页进入目标任务、找到 PRD/检查材料和原始目录；任务阶段与归档位置分别准确；文件缺失或读取失败时不出现“全部正常”的结论。

## 产品边界

| 现在可以做 | 本轮不作为主路径 | 将来重新评估的条件 |
| --- | --- | --- |
| 读取任务、归档、规范、频道记录；查看原件；搜索筛选；保存本地阅读偏好 | 面板内正式规划建任务、拖拽改阶段、标记完成、归档、调度检查代理、根据任务状态自动推动 Jira | 有明确的 AI agent 执行协议、任务与会话绑定、动作回执、权限与失败恢复机制 |

“任务生命周期主路径只读”不否定笔记、规范编辑等独立现有功能。它们的存废不由本提案决定。现有任务写入按钮仍在代码中，需由独立实施任务移出主界面。

## P0：先把事实和主路径做对

### P0-1 任务页重构：单一主从布局，生命周期写入入口全部撤下（2026-09-29 修订）

- **问题**：看板拖动只改写 `task.json` 一个字段，不触发任何真实工作流，是“假装在管理任务”；状态下拉、DoD 完成、任务创建、归档同理。看板/列表/阅读/泳道四种布局加独立详情页（约 2700 行）维护成本高。
- **目标交互**：任务页合并为**单一主从布局**——左侧任务列表（标题、阶段标签、日期、材料圆点），右侧任务详情（见 P0-3）。点击列表行右栏即时切换，不跳页；键盘 ↑↓ 换任务、`/` 聚焦搜索、双击行打开任务目录；窄窗口右栏转覆盖式抽屉。看板、泳道、阅读布局与拖拽一并删除，Tasks 与 TaskDetail 两页合并实现。
- **需核对的入口**：看板拖拽与状态选择、任务详情状态字段、DoD 完成与归档、AI 规划后的创建、从 Jira/待办直达建任务、命令面板相关动作、跨页详情悬浮层，以及后台 `autoSyncJira` 定时回写（Jira 状态直接写 `task.json.status`，与“阶段权威在外部工作流”原则冲突，须停用或删除）。清理范围由实施任务逐项确认，不以删除底层 IPC 作为第一步。
- **验收**：任务页只剩一种主从布局；从概览、待办池、任务页与 Jira 页面均不能把任务推进到新的 Trellis 阶段；后台无 Jira→任务状态自动回写；阅读与外部跳转仍可用。若旧入口因兼容原因暂存，须不出现在主界面，也不能在文案中暗示它等价于 Trellis 流程。

### P0-2 给每条状态加“来源”和“我能确定到什么程度”

- **问题**：`task.json.status`、目录位置、频道 `done`、Jira 工单状态可能不同；原方案把它们压成一个“代理进度”或健康色点。
- **目标交互**：任务阶段注明“来自 task.json”；归档注明“扫描到归档目录”；频道记录显示原消息与时间；Jira 显示独立远端状态和上次成功读取时间。不同来源不自动合并成单一“完成”结论。**标注极简化（2026-09-29 修订）**：列表行与卡片上不放解释句子，仅保留一个小标记（如 `task.json`），悬停才显示完整说明；解释文字只出现在悬停提示、详情页头部与错误态。
- **三种结果**：读到明确数据；没有对应材料；读取失败或数据过期。后两者有不同说明与重试/打开原件入口。
- **验收**：仅有 `in_progress` 而无运行事件时，页面不写“代理正在工作”；只收到频道 `done` 而未归档时，不写“任务已归档”；无法读取频道时，不写“没有待处理事项”。

### P0-3 把任务详情做成材料目录

- **问题**：任务的 PRD、设计、实施、检查与上下文材料散在目录及多个视图，用户要猜哪个文件存在。
- **目标交互**：任务详情顶部保留身份信息与任务阶段，主体按“需求与计划”“实施与检查”“关联与归档”分组。每项显示文件名、是否存在、最近可核实的文件时间，并提供预览及“打开原件”。`implement.jsonl/check.jsonl` 存在时展示引用文件和理由；不存在时显示“未找到上下文清单”，不判任务不合规。
- **验收**：用户无需记文件名即可找到现存材料；缺文件和读取失败显示不同文案；原始文件路径可见，不将自动生成的摘要冒充原文。

### P0-4 重做概览为“项目快照”

- **问题**：旧方案把首页画成代理实时指挥台，但缺少可靠的任务—频道—代理运行绑定。
- **目标交互**（2026-09-29 修订）：概览从统计仪表盘改为**入口页**，回答“变了什么、坏了什么、从哪继续”：① 最近在动的任务流（文件变化时间，行可直达详情）；② 资料体检（读取失败、缺文件的明细入口）；③ 阶段计数与归档数量压缩为一行。顶部固定显示最近扫描时间与读取状态。频道活跃状态仅在有明确事件协议与来源时独立展示。
- **验收**：首页不宣称“几个代理正在工作”“等我处理为 0”或“今天产出了多少”而无证据；重扫描失败时保留上一份快照并标记“可能过期”。

### P0-5 Jira 页对账化重构（2026-09-29 修订）

- **问题**：“加入待办池”只把工单存成 `.trellis/todos/<KEY>.md`，之后无人消费，是死胡同；“AI 规划”在面板内一次生成直接建任务，绕过外部正式研讨流程。两者与“外部干活、面板递料”的定位冲突。
- **目标交互**：Jira 页改为**工单浏览器 + 关联对账器**。① 工单列表保留只读浏览；② 新增“关联对账”视图：已挂钩任务↔工单并排显示本地阶段与 Jira 状态、各自读取时间，不一致仅标注供人工核对，不自动推送任何一侧；③ 未关联工单提供“复制工单摘要”（key、标题、描述、链接），供粘贴到外部 AI 会话作需求输入；④ 保留“关联到已有任务”（`linkExisting` 写 `meta.jiraKey`，是有效挂钩）；⑤ 删除“加入待办池”与“AI 规划”入口；⑥ `autoSyncJira` 后台回写停用（与 P0-1 合并处理）。
- **验收**：Jira 页不再产生无人消费的待办文件；对账视图能暴露“本地阶段与远端状态不一致”且两侧都有读取时间；页面上任何按钮都不触发 `task.json` 状态或 Jira 远端变更。

## P1：提高查找与阅读效率

### P1-1 补齐导航、搜索和术语

- 命令面板补齐现有页面与任务入口，统一“待办池”名称；AI 对话的入口可见性单独优化，但不得因此把它定义为 Trellis 任务规划主入口。
- 搜索优先覆盖任务标题、目录名和已扫描的材料标题；结果标明类别，避免把“任务”“待办素材”“归档”混为一类。
- README 中不存在或已断链的能力以实际产品为准修订；不能为兑现宣传而先做通用命令执行器。

### P1-2 本地阅读视图

- 任务列表支持阶段、优先级、文件是否存在、归档与否等**已具备数据**的筛选与排序；保存为本地阅读偏好。
- 只有在任务与频道、代理的稳定关联经过验证后，才提供“按频道/代理分组”。保存视图不写回 `task.json`，不改变工作流阶段。
- 空结果说明筛选条件，并给“清空筛选”入口；不提示“全部任务已完成”。

### P1-3 频道、Jira 与规范的证据式阅读

- 频道页可把大量进度消息折叠，但保留事件原文、来源频道和时间；不由自由文本自动生成“待我回复”队列。
- Jira 页按 P0-5 完成对账化重构后，P1 仅做读取体验优化（缓存、错误态、字段展示密度），不再扩展入口类功能。
- 规范页可强化引用和索引导航。`rules/business/guides` 三轨属于参考项目定制；无该结构的项目继续按现有包/目录展示，不提供默认迁移要求。

| 候选 | 启动前必须具备的条件 |
| --- | --- |
| 面板内多轮 AI 研讨与正式建任务 | 用户明确选择把面板升级为执行入口；有需求确认、Trellis 任务创建、上下文注入和代理接手的完整协议 |

## 顺序与放行条件

1. **事实基线**：用真实任务样本核对扫描、文件存在、阶段、归档、Jira 关联及错误态；修正旧提案的错误结论。
2. **P0 最小版本**：任务主界面读为主、证据标注、任务材料目录、项目快照一起验收。只改首页而保留误导性的状态拖拽，不算完成。
3. **P1 按使用证据推进**：先观察哪些材料最难找、搜索词是什么、跨页跳转次数，再选导航与阅读视图的细节。
4. **AI agent 平台决策另立项**：只有用户重新决定产品边界且前置协议具备，才从远期候选中取执行功能。

## 风险与保守假设

- 源码静态核对无法证明运行时稳定，实施前需要用真实 `.trellis/` 项目做冒烟。
- 当前 `scan.ts` 中 `TaskInfo.updatedAt` 取任务目录 mtime，不代表“代理最后活动”；设计中不得直接以它计算代理停滞时长。
- 面板现有写入 API 和按钮是代码现状；本提案没有删除它们。实现时应核对所有入口和跨页复用，避免只藏一处按钮。
- “主界面只读任务生命周期”不等于整个应用只读；笔记、规范编辑、设置等另按各自职责评估。
