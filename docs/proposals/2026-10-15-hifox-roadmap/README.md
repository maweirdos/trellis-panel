本路线图根据 HiFox 当前可发现的全部公开文档，以及 Trellis 现有代码、活动任务和历史方案整理。HiFox 提供产品能力参考，Trellis 的实际团队流程决定建设顺序。本文不把参考产品的宣传、默认设置或示例指令当成项目要求。

核心方向：**先让产品、开发、测试沿同一条任务链协作，再让成员按需调用现有编码 Agent，最后把已经稳定的步骤接成自动化。**

## 本轮形成的结果

- 获取 47 个当前可发现的公开文档页面，成功 47，失败 0；包含从正文链接发现的 PingCode 等页面。
- 按团队流程重组为 R0–R5 六个阶段，没有照搬参考产品的菜单层级。
- 每个来源页面均有能力映射和去向；后置、按需接入也属于明确去向，不代表遗漏。
- 没有给出工期承诺，没有替团队选定运行框架、共享存储、部署方式或同步实现。
- 项目内保存原创整理与来源元数据；获取的页面正文仅用于本机研究，没有把第三方整站正文复制进仓库。

2026-10-16 补充：项目提升为窗口根上下文，外部应用统一拓展口已纳入 roadmap、当前不实施。用户明确开发者工具优先多项目启动、基础日志与 Git 查看，不需要代码编辑和调试。后续灵感分为明确方向与候选，未转为实施任务。

获取范围是从 welcome、文档导航及正文链接递归发现的同站 `/docs/` 页面。站点 `sitemap.xml` 返回 404，因此不声称覆盖未公开、需登录或未被任何文档链接引用的页面。获取日期与页面正文指纹见来源索引。

本目录承接 [2026-10-11 统一候选](../2026-10-11-cockpit-convergence/README.md) 的历史讨论，但采用本轮用户明确补充的实际流程。历史方案中的技术初选不因此成为本轮决定。[原 roadmap](../../roadmap.md) 的实现记录和冻结事项继续保留。

## 已确定与待审查

已确定：项目归属清楚、避免重复导航；Jira 保留为现有需求来源；开发将粗需求转成具体需求后交产品确认；当前以真人和手动档为主；执行环境留在成员电脑；Agent 能力优先复用开源方案。

待审查：本稿的能力优先级、阶段出口、真实试点范围，以及哪些拓展方向对团队有价值。路线图通过后，再逐阶段讨论交互细节和技术设计。本稿不表示已批准所有候选能力实施，也不自动新建实施任务。
