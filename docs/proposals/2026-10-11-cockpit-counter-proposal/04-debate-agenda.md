# 04 · 对峙议程与收敛协议

本文件定义两方（GPT 方案 vs 驾驶舱反方案）如何辩论并收敛。目标不是分胜负，是产出一份统一路线图。**用户是唯一裁决者。**

## 1. 辩论规则

1. 引用编号说话：P0x（痛点）、G0x（GPT 章节）、Rx（锐评）、Fx（功能）、Dx（辩题）。不引用证据的论点视为立场噪音。
2. 每条表态标注分歧类型：**事实**（可验证）/ **判断**（工程权衡）/ **优先级**（先后顺序）。事实分歧靠查证代码与文档解决；判断与优先级分歧交用户裁决。
3. 不重写"共同事实底座"；要推翻其中某条，须给出可验证证据。
4. 不引入 01 章证词之外的用户偏好；不得替用户发明需求。
5. 每轮辩论的输出是一张"分歧状态表"，不是一篇新文章。

## 2. 共同事实底座（双方已一致或不应争论的部分）

### 现有代码资产（已核实，2026-10-11 快照）

### 使用环境现实（01 章证词）

## 4. 我方让步区（预先承认 GPT 方案正确的部分，辩论中不争夺）

1. **治理层最终需要**：简报版本化、验收流、角色权限在有真实多角色使用后会成为需求——分歧只在时机（我方：试点后按数据引入；GPT：M1 起）。
2. **防伪原则全盘采纳**：证据等级（配置引用→已传递→运行环境确认加载→检查通过）贯穿 F2/F3/F4，缺证据不升级状态。
3. **Jira 字段所有权**（G06 第 2 节）：优先级/冲刺/正式指派以 Jira 为准，平台操作走意图+回执。
4. **多设备严谨性**：现在不建，但事件 ID 去重 + 单设备假设是最低配，架构上不堵死升级到 epoch/outbox 的路。
5. **客户端减重的测量纪律**（G05 第 6 节）：安装包、装后磁盘、Node/Agent 依赖、首次下载分开报，禁止只报小壳体积。

## 5. 待辩题（双方各给立场与证据，用户裁决）

- **D1 首发用户**：我方＝开发个人（驾驶舱先让自己离不开）；GPT＝全角色（产品/开发/测试同时上）。影响 M1/P0 的全部内容。
- **D2 共享默认值**：自动快照+黑名单 vs 手动策展发布。我方核心反转点（R3）。
- **D3 Brief 的存废**：Jira 增强（抓取+澄清卡）vs 平台一等对象（BriefRevision）。R2 的落地形态。
- **D4 服务器出现时机**：P3（先用本地+基座仓库 CI 静态面板）vs M1（Web 服务+账号先行）。
- **D5 工作流可视化的降级边界**：外部编辑器只给"推断"标注是否可接受；是否以"舱内满血"作为统一驾驶舱的软性牵引。
- **D6 业务规范路由的证明天花板**：留痕三层（检索有据+注入有痕+检查对照）是否足够，还是必须更多。
- **D7 飞书抓取**：进 P2 还是降为可选（取决于公司应用权限的现实约束，属事实型辩题，需先查证）。
- **D8 验收与治理功能的引入判据**：采用 G05 第 7 节触发条件表，还是另定（例如"第二个非开发角色开始每周打开面板时"）。

## 6. 收敛协议

1. 每轮辩论输出**分歧状态表**：编号 / 类型（事实|判断|优先级）/ 我方 / GPT 方 / 状态（已收敛|待用户裁决|需补证）。
2. 事实型分歧：双方各自查证后更新底座，不投票。
3. 判断与优先级分歧：用户裁决后标记"已裁决"，写入统一路线图，不再重开。
4. 最终产物：**统一路线图 v1.0**——每行 = 功能（F 编号或新增）→ 来源痛点（P 编号）→ 阶段（P0–P3 或重排）→ 验收标准 → 归属（我方/GPT/融合）。路线图一旦经用户确认，取代两份原方案成为唯一实施依据。
5. 辩论禁止事项：不新增无证词支撑的"用户想要"；不用"业界都是这样"替代证据；不因沉没成本扩大范围（继承 G07 第 8 节停止条件精神）。
