# 03 · 任务驾驶舱反方案

一句话定位：**不做编辑器，不做流程法庭，做驾驶舱。** 飞机由 agent 开（各家 AI 编辑器/agent 作为子进程通过 ACP 接入），仪表盘、检查单、拉杆在驾驶舱里——仪表盘是注入回执、工作流进度、知识轨迹；检查单是 PRD/design 的舒适阅读与确认门；拉杆是权限批准、钉规范、挂子任务。

## 1. 产品命题

用户所有痛点同构（见 01 章归纳）：AI 在 trellis 里做的每件事对人都是黑盒。本产品把 trellis 的执行过程从"文件结果"升级为**可看、可评、可续的界面**。面板是只读的玻璃（P01 初衷），agent 平台是能伸手进去的玻璃（P09 动机）。执行发生在 agent 会话里，外部产品永远只能看落盘结果——这就是必须把 agent 拉进项目的理由，也是唯一护城河：AI 厂商不会为 trellis 的 spec/task/channel 语义做仪表盘。

## 3. 一天场景走查

早上打开面板：版本看板 → 认领 PAY-231 → 一键"起任务"：建 trellis 任务、抓飞书需求章节进 docs。agent 起草 PRD，在舒适阅读器里读，勾掉两句、留一张澄清卡发产品。确认 design → 门开 → 实施页：工作流管道图显示主 agent 已派"后端""前端"两个泳道；注入回执显示 5 条编码规范全绿、业务规范只命中 1 条——手动钉上"追溯码业务规则"（F7）。agent 要跑 git push，权限卡弹出，点允许（F6）。检查阶段：规范清单 vs 检查结果对照，2.2 质量检查标"未观察到证据"，让它补跑（F3）。交付有坑 → 挂子任务（F10）。两周后产品提优化：关联任务树，前情提要一页纸接上，不用重头讲（F9）。归档：自动提交基座仓库、摘要进迭代 KB、Jira 回写（F13/F11）。产品视角：一个只读链接，实时看到任务 PRD 现状与阶段——他不需要装任何东西（F1/F3 的只读直播）。

## 4. 对 GPT 方案的处置

- **全盘吸收（宪法层）**：防伪原则（R0-1，贯穿 F2/F3/F4 的证据等级：配置引用→已传递→运行环境确认加载→检查通过，缺证据不升级）；边界纪律（R0-2，人批准、不远程执行）；Jira 字段所有权（G06 第 2 节）；开源模块选型结论（G05）。
- **反转两条**：共享默认值——自动快照 + 黑名单替代手动策展（R3）；Jira 定位——需求入口而非回写目标（R2）。
- **延后但保留触发条件**：简报版本化、验收流、权限治理、多设备严谨性（epoch/租约/outbox）→ 移至试点验证之后；采纳 G05 第 7 节的触发条件表作为引入判据。

## 5. 诚实的边界（哪里只能做到七成）

- **满血与降级双模式**：工作流可视化在"舱内 agent"（ACP + channel 事件）满血；员工用外部编辑器跑时只能靠 watcher 文件变化推断，界面必须诚实标注"推断"。这自然推动团队统一用驾驶舱，因为只有舱内满血——但不禁止外部编辑器（trellis 本就多平台）。
- **业务规范路由无法 100% 证明**（模型内部推理不可见）。天花板 = 检索有据（F4）+ 注入有痕（F2）+ 检查阶段验证（trellis-check 对照注入清单）。不追求读心，追求留痕。
- **飞书抓取**依赖公司应用权限，先备手动粘贴兜底；标题/章节匹配预计八成自动。
- **ACP 兼容**只承诺团队实际用的两三种 agent，其余走降级观察，不以 logo 提前许诺（与 G05 第 5 节一致）。
- **不承诺一次做对**：每个 P 阶段结束按真实使用数据决定继续、缩小或替换（继承 G07 第 8 节的停止条件精神）。

## 6. 落地路线（先无服务器，全部本地起盘）

| 阶段 | 内容 | 对应痛点 | 验收要点 |
| --- | --- | --- | --- |
| P0 玻璃盒三件套 | F1 补全（差异/结构化）→ F2 注入回执 → F3 工作流进度图 | P01/P02/P03 | 纯本地文件与事件，无账号无服务器；两周量级见东西；回执有证据等级，缺证据不绿 |
| P1 驾驶舱化 | F5–F10：ACP 控制台升级为驾驶舱（权限卡、确认门、澄清卡、钉规范、子任务树、前情提要包） | P03/P04/P09 | 一次真实复杂任务全程在舱内完成；前情提要包让隔期优化任务不再从零开始 |
| P2 外循环 | F11 Jira 版本看板 + 认领回写；F12 飞书抓取；今日工作台 | P05 | 认领→起任务→归档回写全链路人工操作压到一分钟内 |
| P3 团队聚合 | F13 归档即提交 + 迭代 KB；F14 进度线（先基座仓库 + CI 静态面板，跑顺后加小服务做认领与飞书通知）；视试点数据决定是否引入 GPT 方案的治理层 | P06/P07/P08 | 团队成员零安装可看；迭代时间线可从 KB 反链任务树 |

执行哲学：先把"黑盒变玻璃"做到让每个开发离不开，团队功能被"大家都能看见"自然拉出来，而不是靠流程要求大家填表。exe 体积问题随主线解决：Web/面板成为主界面后，本地端收敛为"伴随服务 + 浏览器打开 localhost 工作台"，Electron 壳降级为可选安装（继承 G05 第 6 节的测量纪律：安装包、装后磁盘、Node/Agent 依赖分开报）。
