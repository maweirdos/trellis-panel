# 任务驾驶舱 · 反方案与对峙手册

版本：v0.1 · 2026-10-11 · 性质：与 `../2026-10-11-local-team-platform/`（下称"GPT 方案"）并行的反方案，兼作两方辩论的议事规则。

## 这套文档是什么

用户先向 GPT 要了一份团队平台方案（GPT 方案，9 章），随后以本人真实开发体验逐条对照，结论是"想得太理想"。本目录固化三样东西：

1. **用户一手证词**（01）：真实痛点，是辩论的证据底座，任何一方不得改写。
2. **对 GPT 方案的锐评**（02）：五个硬伤与三点信用，逐条可回应。
3. **任务驾驶舱反方案**（03）：从证词推导出的产品概念与落地路线。
4. **对峙议程**（04）：共同事实底座、分歧清单、让步区、收敛协议。

## 阅读顺序（给参与辩论的 AI）

01 → 02 → 03 → 04。然后在 04 的辩题上逐条表态：引用编号（如 P03 / R2 / F9 / D4），标注分歧类型（事实 / 判断 / 优先级），给出证据或让步。不要重写已列入"共同事实底座"的内容，不要在无证据处坚持。

## 辩论目标

不是分胜负，是收敛出一份统一路线图：每个功能标注它来自哪个痛点、排在哪个阶段、验收标准是什么。**用户是唯一裁决者。**

只新增本目录文档。没有创建 Trellis 任务，没有修改产品代码与依赖，没有接入真实 Jira / 飞书 / 模型 / Agent。所有可行性判断均标注证据来源；未实测的一律写明"未验证"。
