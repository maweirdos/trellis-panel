# 完整流程与异常交互

## 从 Jira 粗需求到可交付工作

以“门诊处方皮试液自动带出”为界面示例，业务规则由团队确认；此处只设计协作流程。

| 步骤 | 谁从哪里进入 | 主工作区内容 | 主动作与结果 |
| --- | --- | --- | --- |
| 产品调研 | 产品在现有 Jira 记录调研与粗流程 | 原始问题、背景、现有截图和不确定项 | 保留粗需求，允许信息不完整 |
| 接入项目 | 开发在项目需求接收选择 Jira 来源 | 原始内容、已有本地关联、缺失信息与接入目标 | 接收为工作项；重复来源打开原工作，不再建副本 |
| 具体需求 | 开发进入工作项的需求与决策 | 结合本机代码整理的流程、边界问题和验收草稿 | 提交指定版本给产品确认 |
| 产品确认 | 产品从待我处理进入同一工作项 | 当前提交版本、原始来源和需要决定的具体问题 | 确认版本，或留下对应内容的修改意见 |
| 补充与定稿 | 开发处理意见 | 变更差异、已采纳项、仍有分歧的项 | 没有新变化直接继续；有变化只确认受影响内容 |
| 技术规划 | 开发切到计划与执行 | 设计、拆解、依赖、验证方法及 Trellis 必要规划材料 | 满足既有规划/实施授权要求后进入实现 |
| 实现与检查 | 开发在同一工作项推进 | 真人执行记录，或本次 Agent 运行与检查成果 | 提交可复核结果，不把运行结束当作验收 |
| 技术与业务复核 | 指定复核人从待处理进入 | 代码/测试版本、证据、业务验收标准和已知问题 | 各自形成结论；退回时说明具体差异 |
| 交付与沉淀 | 负责人确认交付范围 | 发布记录、Jira 待回写内容、后续工作和文档缺口 | 明确执行回写、归档或生成经验草稿 |

侧栏持续显示当前项目的并列模块。工作项标题、版本、当前责任人和下一步动作随流程保留。产品不需要配置模型，测试不需要翻开发终端，开发不用重新拼接所有上下文。

跨机器评审需要共享明确版本的材料和确认记录。若试点仍通过显式发布材料包交接，应显示发布版本和人工交接状态，不能称为已实现实时团队协作。

## 知识如何跨越整个流程

开发细化需求时，从辅助区打开知识检索，默认当前项目。结果显示需求、规范、Wiki、既有经验及可访问的公司来源。开发阅读原文后可以引用某一段和版本；提交产品确认时，产品可沿引用打开同一依据。

技术规划阶段，“加入本次执行材料”会展示将携带的文件、版本和来源范围。用户确认的是本次材料集合，后台实际发送的回执单独保留。外部公司库查询失败时，本地资料仍可用；没有权限的来源不能伪装成空结果。

交付后可以把一次解决方法整理为经验草稿，关联原工作项和证据。草稿经过采纳、确定适用范围后进入知识检索。聊天结论不会自动成为正式规范，也不会自动扩大到其他项目。

## 真人与 Agent 共用同一工作区

“计划与执行”首先支持人工推进。开发选择调用 Agent 时，打开紧凑的本次执行面板，显示任务、材料版本、角色、工具、机器和目录；主动作是“开始本次执行”。

执行后中央可切到对话或运行视图，任务标题与阶段仍在。相关文档、Diff 和检查结果按需打开。需要授权时，待决事项内联显示给有权处理的人；切走再回来仍可发现真实待决项。

Agent 完成后生成结果摘要、改动与检查证据。负责人选择采纳、继续修改或提交复核。普通评论、指派、切状态、切项目均不隐含启动编码。手动调用稳定后，再逐步开放流程触发与自动化；两种模式沿用同一任务和材料。

项目会话目录可以重新打开任务关联对话。长会话在中央展开阅读，旁边提供任务摘要；返回任务时恢复原来的材料位置。不会再出现两套同名会话目录。

## 需要明确处理的场景

| 场景 | 界面与操作约定 |
| --- | --- |
| 需求还不清楚 | 保持待细化，显示待问问题和责任人；允许先接收，不要求虚构完整验收标准 |
| 确认后改规则 | 标记确认针对旧版本，比较变化与影响；只请求相关人重新确认受影响部分 |
| 两个人同时改材料 | 提示版本变化并提供比较/协调入口，不静默覆盖；确认结论始终绑定明确版本 |
| 产品暂时不在线 | 工作项显示等待指定人，个人与团队队列可找回；不推断已读即批准 |
| 开发请假交接 | 新负责人看到来源、需求版本、决策、方案、代码基线、检查和未决事项；切换执行目录需明确 |
| 同任务包含多个工程任务 | 父工作项保持业务目标，工程子项维护自己的状态和结果；父项不因单个子项结束就验收 |
| 紧急修复插入本轮 | 标明紧急原因、最小范围和必要复核；记录对本轮计划的影响，保留后补材料义务 |
| 迭代到期未完成 | 保留原轮次结果，给出结转/退回规划/取消的明确选择；日期结束不改变任务完成事实 |
| 机器在线但工具不可用 | 分别显示连接、工具、登录、路径问题；提供本次任务的恢复入口，不带用户泛跳到设置首页 |
| 同目录并发冲突 | 解释排队或选择隔离目录；不静默把工作切到其他机器或覆盖别人的目录 |
| 切换 Runtime | 先形成已确认材料、代码基线、结果与待办的交接；原生历史能否恢复按真实能力呈现 |
| 执行完成但回写失败 | 保留执行成果，分别标记已成功与待补动作；重试只补失败部分，避免重复建任务或评论 |
| 运行是否已执行不确定 | 标为待核实；查看记录后继续，不自动重发可能有副作用的请求 |
| 测试包缺目标提交 | 停留在版本核验，解释不匹配；不把其他版本通过的结果算作当前需求通过 |
| 搜索跨到公司资料 | 用户主动选择范围，来源醒目标记；权限不足与无结果分别提示 |
| 未打开项目 | 引导打开本地项目；进入演示时整页标演示范围，不显示仿真的个人待办为真实数据 |
| 切换项目 | 列表、选中任务、收藏、视图、会话与材料按项目恢复；未保存草稿先明确保存位置或处理方式 |
| 从通知或深链进入 | 直接到正确项目、工作项和待处理位置；材料打不开时说明原因并保留回到来源的路径 |

## 高频操作与返回路径

全局搜索用 Ctrl+K，默认当前上下文，并允许显式扩大范围。结果分清工作项、文档、会话、成员和导航；点击对象直接打开它，不先进入无关列表。具体检索源仍受已实现能力和权限约束。

Ctrl+B 折叠上下文侧栏，保留范围栏。Esc 逐层关闭菜单、辅助区、预览，并恢复触发位置的焦点；编辑中先处理草稿，不清空整条任务。返回列表时恢复筛选、分组、滚动和选中项。

创建按钮受当前位置约束：需求接收创建/接收需求，工作项创建工作项，文档创建草稿，会话创建当前项目对话。全局新建菜单先明确对象类型和目标项目，不以一个模糊“+”暗中猜范围。

外部写入、发布、权限调整等动作在操作位置展示实际影响。普通打开、阅读、筛选无需反复确认；审批确认的是具体版本和决定，运行授权确认的是当前工具请求，两者不混用。
