# 信息与数据边界

## 范围 对象 与视图

| 类别 | 本方案中的对象 | 判断规则 |
| --- | --- | --- |
| 工作范围 | 个人、项目、知识、执行资源 | 决定当前导航和可以访问的数据范围 |
| 工作对象 | 工作项、文档、会话、迭代、成员、运行 | 有稳定身份、来源、状态及历史 |
| 查看方式 | 我的任务、待我确认、看板、列表、按周期分组 | 查看已有对象，不产生第二份任务或材料 |
| 操作 | 接收、指派、请求确认、执行、回写、归档 | 改变特定对象；显示影响范围、执行结果和失败原因 |
| 配置 | 项目流程、连接、角色模板、个人偏好 | 明确生效范围和维护者；不隐含启动业务动作 |

工作项是可交接的基本单位，迭代、团队和统计是并列组织视角。文档和会话可独立存在，也能明确关联到工作项；不能为每种入口复制一份数据。

## 任务的三个状态维度

| 维度 | 示例 | 在界面中怎样出现 |
| --- | --- | --- |
| 工作阶段 | 需求细化、待产品确认、技术规划、实现、验收、交付 | 工作项标题附近的主要阶段标记 |
| 运行状态 | 未运行、排队、执行中、等待授权、失败、已停止 | 有运行时在执行区显示；必要时摘要到任务列表 |
| 待人处理 | 请产品回答边界问题、请开发补证据、请测试验收 | 个人待处理与团队交接队列，明确责任人和下一步 |

业务阶段名称须与当前 Trellis 的 planning/in_progress/review/completed 及 Phase 1–3 做映射设计，不能只靠拖动卡片推断阶段或授权。产品确认、工程规划审查、技术检查和业务验收各有自己的结论，界面不能用一个“通过”替代它们。

## 材料与知识的权威

| 材料 | 权威与范围 | 允许的联系 |
| --- | --- | --- |
| Jira 调研与粗需求 | 外部原始来源，保留编号与更新时间 | 引用到工作项；按明确动作接收和回写 |
| 开发整理的具体需求 | 结合项目代码与业务形成的工作材料 | 产品确认指定版本；后续变更比较差异 |
| prd.md / design.md / implement.md | 当前工程材料，具体规则遵循 Trellis | 页面提供真实文件阅读、版本与编辑来源，不擅自重写全部文件 |
| 规范和 Wiki | 原始文件或已授权知识源 | 直接打开、带版本引用、按明确范围加入执行材料 |
| AI 回答与会话总结 | 辅助产物，有来源和生成记录 | 可形成待确认草稿；采纳后再发布为正式材料 |
| 检查报告与交付证据 | 对应具体运行、代码/测试版本和用例 | 验收可引用，临时目录清理后仍应可复核 |
| 个人草稿 | 只在真实私有存储与权限成立时称为私有 | 发布副本需明确范围；现有项目 `.trellis/notes` 不自动等同私人存储 |

知识中心负责索引和访问这些材料，保留原始来源，不成为一套新的规范编辑权威。新建可复用经验时明确作者、来源任务、适用项目、采纳状态与后续维护人。

引用、加入本次上下文、复制到新草稿、发布到团队是四个动作。引用不自动传给模型；已发送记录也不证明模型实际遵守。当前任务与本次执行使用的材料版本始终能区分。

## 项目 文档 会话 与执行

项目是协作范围，不直接等于一个工作目录。项目可绑定仓库和来源，执行时还需明确具体机器、目录和代码基线。现有单仓库项目先保持简单，不提前增加工作区、空间和组织的重复容器。

项目会话目录是正常用户的唯一项目级会话入口。从任务打开其关联会话时，访问同一条记录。未关联任务的探索对话仍属于明确项目，可由用户将结论形成工作项或文档草稿。

旧通用 API 问答没有可靠项目身份，暂在执行资源中的“模型调试”保留兼容访问并标注跨项目；正式并入项目会话需另行处理数据归属。Trellis channel 等技术协作通道先保留在高级诊断入口，不把底层协议频道伪装成人员讨论区。

Agent 配置定义职责和可用工具，本次运行才确定任务、Runtime、机器、目录、材料版本与权限。项目会话、Agent 模板和运行历史分别表达，切换项目不会停止其他项目的运行，也不能串用其记录。

## 设置的生效层级

| 层级 | 设置示例 | 当前运行如何受影响 |
| --- | --- | --- |
| 个人偏好 | 主题、通知、阅读宽度、快捷键 | 只改变本人视图和提醒 |
| 资源定义 | 连接凭证、Agent 模板、可用 Runtime、电脑 | 更新默认资源信息；已有运行保留绑定及有效性检查 |
| 项目绑定 | 可用资源、仓库、Jira 范围、项目规范、协作规则 | 用于新工作/新执行的默认值，变更说明影响 |
| 本次覆盖 | 当前角色、模型、目录、材料版本、权限 | 只影响当前动作，显式保存后才改变默认值 |

已保存的资源不能绕过操作者权限。普通成员可完成真实人工流程；管理设置按真实权限呈现，不根据截图或本机开发者名字自动授予管理员身份。

## 现有页面的落位

| 现有能力 | 新布局位置 | 处理方式 |
| --- | --- | --- |
| YourWork / dashboard | 我的工作 | 优先列待行动，不再用欢迎语和维护提醒占据中心 |
| WorkItems / tasks | 项目协作 → 工作项 | 复用布局、筛选、保存视图、收藏与任务身份 |
| inbox 待办池 | 项目协作 → 需求接收 | 作为接收与整理队列，先核对其真实来源规则；不冒充个人通知中心 |
| Jira | 项目协作 → 需求接收 → Jira 来源 | 保留外部查询、来源编号、接收与同步反馈 |
| 周周期 | 项目协作 → 迭代计划 | 保留本轮范围、结转及历史，避免变成工作项的隐藏分组选项 |
| Archive | 工作项的已归档范围 | 任务归档与知识经验仍分别表达 |
| Team | 项目协作 → 团队 | 先复用成员工作、日志、交接视角；真实多人协作分期补齐 |
| Analytics | 项目协作 → 统计 | 队列、等待、完成与范围变化；按任务穿透 |
| Knowledge | 知识中心与项目文档的统一来源 | 项目材料、公司库、个人来源明确标记，不复制实体 |
| Spec | 项目文档 → 规范与工作记录 | 保持真实文件阅读、版本和权限 |
| AcpConsole | 项目协作 → 会话及任务关联运行 | 复用按项目隔离的记录，执行控制可就地打开 |
| Chat | 执行资源 → 模型调试，兼容阶段 | 保留旧跨项目历史，不自动认领到当前项目 |
| Channels | 执行资源 → 高级诊断 → 协作通道 | 保留技术能力，后续按真实产品场景决定是否形成普通协作入口 |
| Architecture | 项目文档 → 架构视图 | 关联项目资料与任务，支持展开阅读 |
| Studio | 项目设置 → 工作流与扩展 | 项目规则与复用资源分别说明，不复制第二套角色管理 |
| Models | 执行资源 → 模型与运行工具 | 资源维护入口，普通任务不要求先打开它 |
| Gateway | 执行资源 → 工具与连接 | 配置范围与实际执行的项目上下文分开 |
| Settings | 个人设置、项目设置、执行资源设置 | 现有配置按生效范围重组，具体迁移实现后续讨论 |

此表是产品落位，不表示可以只移动菜单就完成共享权限、真实评审、历史迁移或统一运行层接入。
