# 03 · 页面与交互流程

## 1. 界面原则

任务上下文始终可见：需求编号、采用版本、真人责任人、当前所在位置（团队空间/我的本机）。主操作只给当前角色能执行的动作。进度使用真实阶段与待处理问题，不编造百分比。

需求助手的对话与“简报草稿”并排；开发工作台的主区域是工程材料与步骤；测试的主区域是验收项与共享证据。三种页面不能只是换了角色头像的同一个聊天窗口。

原型采用浅色工作台、克制的蓝绿色强调、清楚的文档层级。样式是初版方向；本轮重点验证职责与流程。

## 2. 页面清单与主操作

| 页面 ID | 页面与角色 | 默认内容 | 主操作 | 必须避免 |
| --- | --- | --- | --- | --- |
| P01 | 我的工作，所有人 | 与本人有关的待处理事项 | 打开具体事项 | 排名式员工效率分 |
| P02 | 需求工作区，产品 | 需求简报、助手、来源和疑问 | 保存草稿/发布需求版本 | 显示代码仓库与编码 Agent 选择 |
| P03 | 待接需求，开发 | 已发布简报、指派人、待确认项 | 领取并去本机评估 | 领取即开始执行 |
| P04 | 本地工程准备，开发 | 项目绑定、只读分析、工程文档 | 绑定项目/开始项目分析 | 云端指定本地绝对路径 |
| P05 | 工程工作台，开发 | PRD/design、规范清单、阶段事件 | 确认计划/开始实施/暂停 | 用文件变更推断规范已遵守 |
| P06 | 交付发布预览，开发 | 可共享摘要、证据、范围 | 发布交付包 | 默认上传完整工作目录 |
| P07 | 业务验收，验收者 | 验收项、共享材料、版本 | 通过/退回并说明 | 仅因 Agent 回复完成而通过 |
| P08 | 知识与规范，项目成员 | 已发布资料、来源、适用范围 | 查资料/提出规则 | 草稿规则被当作强制规范 |
| P09 | 规则评审，维护人 | 提案前后差异、证据、影响 | 发布版本/退回 | 直接写入所有员工仓库 |
| P10 | 连接与同步，授权成员 | Jira 回执、设备、个人模型工具 | 修复连接/重试同步 | 共享别人的个人凭据 |

## 3. 角色页面线框

### 产品的需求工作区

```text
需求 PAY-128 / 退款重试       草稿 v2        [发布给开发]
业务说明 | 开发反馈 | 交付 | 历史
┌───────────────────────────┬────────────────────┐
│ 目标 / 用户场景 / 不做什么   │ 需求助手            │
│ 验收项 AC-1…AC-4           │ 业务知识与来源       │
│ 待开发核实事项              │ 问题 / 修订建议      │
│ 项目能力摘要：更新时间      │ [应用到简报草稿]     │
└───────────────────────────┴────────────────────┘
研发进展：待评估；没有仓库、终端、Agent 调度入口
```

### 开发的本机工作台

```text
我的本机 / payment-service   PAY-128 · 采用 Brief v2
[本地项目] [当前分支] [本机 Agent]    [开始实施]
┌───────────┬──────────────────────┬────────────────┐
│ 分析       │ 当前工程文档正文      │ 本次规范与来源   │
│ 规划       │ PRD / design / plan │ 已选入/已加载    │
│ 实施       │ 与上个版本的差异      │ 待处理疑问       │
│ 检查       │ 本地测试与代码入口    │ 工具详情可展开   │
└───────────┴──────────────────────┴────────────────┘
共享摘要与完整本地材料分别标识；发布前查看受众和内容
```

### 测试的交付验收


## 4. 关键交互契约

### I01 产品澄清与发布

进入 P02，填写目标和业务范围，点击“补充验收建议”。助手引用已授权资料，并给出可编辑建议。点击“采用建议”只修改草稿。发布时检查基本信息、真人接收方和待评估问题；保存不可变简报版本，创建 Jira 写回请求。即使 Jira 暂不可用，也显示“已发布/关联待同步”，不能伪造工单编号。

需求可在有明确列出的技术疑问时发布给开发评估。发布不是批准实施。

### I02 开发领取与本地绑定

P03 点击“领取”只更新业务负责人/领取记录。点击“在本机评估”唤起已安装本地工作台，显示任务编号与简报版本。开发选择本地项目；路径只在本地保存。未安装时显示安装引导与复制交接材料，不把 HTTPS 页面直接变成远程终端。

### I03 项目分析与反馈

开发先只读分析。结果分为：可以实现、需要澄清、现有行为与需求冲突。选择一个问题，编辑对产品可见的摘要后提交。产品收到的是业务问题，源码证据只作为本地关联。原型用预置分析结果演示，不调用任何模型。

### I04 正式 Trellis 规划

开发采用已回复的简报版本，选择“创建或关联工程任务”。任务路径、真实存在的文档和当前工作流都可检查。按项目要求生成 PRD/design/实施清单；开发确认前不能点击开始实施。轻量任务根据原工作流省略不必要产物。

### I05 中途需求变化

开发工作台另有“与本机 Agent 交流”区域，可补充约束、要求解释或调整工程计划。运行中补充在受支持的工具边界交给 Agent；不支持时明确排入下一轮。对话是开发私有材料，不随阶段摘要或交付副本上传。切换 Agent 应结束旧写入执行并做材料交接，而非直接改变运行中会话的配置。

产品发布 Brief v3 时，正在执行的 v2 保持原样。开发看到差异与影响提示，可先暂停、请求澄清，或记录继续当前安全步骤的决定。变更必须在进入下一受影响阶段前处理。采用新版后更新工程材料，并使受影响的旧验收结论失效。

### I06 发布交付包

显示将上传的完整共享内容与接收范围。默认包含业务摘要、验收覆盖摘要；截图、技术摘要按项目模板和开发选择加入。源码、绝对路径、密钥、终端原文默认排除。机器检查只是辅助，开发可以编辑、删除字段。首次设置共享模板可授权后续同类阶段事件自动同步，不要求每条无敏感事件都重复审批。

### I07 验收与同步

验收者确认具体交付版本的每项结果。退回必须关联失败项；“通过”不授予合并代码权限。完成条件由项目配置确定，满足后才触发 Jira 流转。失败时可重试同一同步意图，而非新建重复评论。

### I08 规则发布

开发将经验转成规则提案，维护人检查适用项目、旧规则冲突、证据与例外。发布产生新版本。员工本机看到可引入的更新提示，由开发按项目规范变更流程落入 `.trellis/spec/`；不从团队服务静默覆盖工作目录。

## 5. 空态与错误态

| 状态 | 应用文案示例 | 恢复入口 |
| --- | --- | --- |
| 产品无代码证据 | “此结论来自已发布资料，待开发结合当前项目核实。” | 添加待核实事项 |
| 开发未绑定 | “领取成功。选择你的本地项目后才能开始分析。” | 绑定本地项目 |
| 项目冲突 | “已有对应工程任务，请确认是否关联。” | 对比任务与 worktree |
| 来源过期 | “该资料超过建议有效期。” | 查看来源/请维护人更新 |
| 运行端离线 | “最近收到进展：10:24。设备目前离线。” | 在本机查看/恢复同步 |
| 审批版本过期 | “交付内容已更新，请重新确认受影响的验收项。” | 查看版本差异 |
| 评论失去锚点 | “原段落已变化，讨论仍保留。” | 手工重新关联 |
| 模型额度不足 | “当前账户无法继续，已保留任务现场。” | 开发更换自己的配置或申请额度 |

## 6. 通知策略

通知只对应需要行动的事件：新指派、澄清待答、需求变更、验收待处理、规范更新、持续同步失败。打字流、每次文件保存和每个工具调用不进入全员通知。

业务讨论、开发私有对话、共享摘要分别保存。产品不能通过“展开日志”穿透本机边界。管理看板关注交付阻塞和等待时间，不采集员工所有编辑器行为。

## 7. 原型覆盖说明

原型包含四种演示角色（产品/开发/验收/规范维护）、五个预置场景、可编辑简报、领取与绑定、两阶段规划、规范回执、交付发布、验收、Jira 失败重试、需求变更和设备离线。完整核验清单见第 09 章。
