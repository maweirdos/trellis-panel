# 账号、组织与本机开发

## 基本关系

每个人使用自己的团队服务账号。团队是组织成员的范围；工作区属于一个团队；空间属于工作区，任务属于空间。本机电脑、工程、Git 仓库和启动配置用于执行任务，不等同于团队账号或空间。

不登录时可以使用本机个人数据。本机数据不会因为登录而自动上传或与团队任务合并。

## 建立协作

1. 管理员部署团队服务，向成员提供大家都能访问的服务地址。
2. 管理员使用个人账号登录，创建团队、工作区和空间。
3. 管理员创建指定接收账号的邀请，核对团队、工作区、职责及可选的空间范围后复制链接。
4. 成员注册或登录邀请指定的个人账号，核对邀请内容后接受。
5. 没有指定空间的邀请只授予团队和工作区权限。成员可加入公开空间；私有空间需要有权限的现有空间成员授权。

练习服务地址 `127.0.0.1` 只指当前电脑。跨电脑协作必须使用所有参与者能访问的服务地址；生产环境应使用 HTTPS。

## 桌面账号与工作区

桌面左下角头像打开“账号与工作区”。“本机个人使用”不需要登录；团队本地账号可以在桌面内注册或登录。登录后可创建组织和工作区，或粘贴邀请链接加入已有工作区，再连接当前电脑。连接后选择已有空间、加入公开空间，或创建空间；私有空间需要获得授权。

每条桌面连接固定到原服务、账号、工作区和设备。添加另一账号或工作区需要新的授权。切换前保存未提交的编辑；原账号的待同步操作不会转给其他账号。已发出但结果不明的操作，需要由原账号核对。

桌面账号会话和设备连接分别管理。退出账号会清除本机保存的账号会话，但不会自动断开设备；断开电脑连接只锁定本机连接。需要撤销服务端设备授权时，在网页设备管理中操作。GitLab/OIDC 桌面账号接入尚不可用。

## 从团队任务进入开发

在任务中选择桌面开发后，核对当前账号、空间、任务和处理人，再选择本地工程。根据任务的代码资源核对实际仓库、分支及工作副本；启动服务前核对运行配置、环境和端口。切换账号或工作区不会自动切换仓库、启动服务或转交本机开发绑定。

运行中的服务和待处理结果保留其原来源。来源、账号、服务实例或任务身份不能核对时，不应将它们当作新任务的执行结果。

## 服务与网页更新

当前团队网页的账号隔离核对需要匹配版本的团队服务。先更新团队服务，再更新网页；旧客户端可以继续连接新服务。更新前保留原团队数据库和资料，使用现有备份和恢复流程。
