# 历史对话与任务的空间分区方案

每条对话只属于一个分区。在个人区开始的对话归个人区，在团队空间开始的对话归该空间。同一组织下的两个空间也各有自己的历史。空间决定用户在哪里看到对话，创建者身份决定谁能读这条私人对话。成员协作通过明确共享的任务和材料进行。

## 切换空间

- 从 A 切到 B，立即收起 A 的正文、搜索结果、任务卡和附件预览。恢复 B 上次选中的对话和草稿；第一次进入 B 时显示空列表和新对话入口。切回 A 后恢复 A 的阅读位置和草稿。
- 侧栏、置顶、最近访问、搜索、归档、命令面板和通知预览都按当前账号和分区读取。直接打开会话链接也要在主进程校验所有者、当前分区和访问权限。目标不匹配时，只提示切回原空间，不返回正文或标题。
- 发送消息时固定账号、分区、会话和运行身份。A 中已开始的回复可以继续生成，分片、工具结果和完成事件只写回 A。切换后的输入只发往 B 当前选中的会话；B 尚未就绪时禁用发送。旧请求即使更晚返回也不能覆盖 B 的列表或输入框。

## 数据与任务绑定

新建会话时持久化所有者和分区。个人区记录个人身份或本机配置身份；团队分区记录服务实例、账号、组织、工作区和空间的稳定 ID。空间改名和设备重连沿用原分区。源服务恢复或身份存疑时先核验原绑定。Work、Code 和主题分组作为分区内的筛选条件，实际工程目录沿用原执行绑定。

列表、单条读取、搜索、发送、文件预览和草稿恢复使用同一套分区校验。切换账号、退出组织或得知空间权限撤销时，关闭旧阅读器、清空界面结果并拒绝后续读取。新账号无法认领另一已知账号的私人历史。

在空间里创建或绑定任务时，只列该空间中当前成员可操作的任务。关联保存原服务、工作区、空间、任务 ID 和创建时间，服务端仍校验权限。A 的对话和任务留在 A，B 的同编号任务不会接管关联。若同事需要这项工作，可由用户明确选择有权导出的材料，在 B 创建独立任务。

## 已有历史

升级时保留原始对话和任务数据。对已有明确所有者、且任务回执或成员绑定能唯一证明原空间的历史，补录该分区。已知本机来源的对话归原本机个人区。来源不明或存在多个空间绑定的历史，放在原所有者专用的「待归类」入口，由本人核对；未能确认所有者的记录留在原本机配置中。不得按最近登录账号、当前空间、任务展示编号或同名空间自动归入团队。归类操作可重试，沿用同一条会话，不复制正文。

## 验收场景

在同一组织的 A 和 B 分别创建同名对话和同编号任务。A 中写一份草稿、发起另一条流式回复，中途切到 B。B 的侧栏、搜索、通知和快捷入口均不出现 A 的内容；在 B 发送消息只进入 B 的会话。切回 A 能看到原草稿、完整回复和正确的任务。再用跨组织、换账号、撤销空间成员权限、重启和旧历史重复归类覆盖相同边界。
