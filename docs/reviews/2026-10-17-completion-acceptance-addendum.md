## 1 先固定本次到底交付什么

每次实施开始前在现有任务/交接文档保存以下小表即可，不需要新建审批系统。

| 项 | 需要明确的内容 |
| --- | --- |
| 依据版本 | roadmap文件路径与指纹，代码HEAD及相关未提交文件指纹；不能只写“最新版” |
| 本次选中 | 具体工作包和原子行为ID；例如选PF-04的普通创建错误反馈，不代表选全部需求接入平台 |
| 本次排除 | 已有能力仅回归、明确不动的模块、可选方向、暂缓/不采用项；包括是否涉及ACP、真实外部动作或跨人场景 |
| 交付结果 | 改完用户从哪个入口，用什么输入，会看到什么实际结果 |
| 验收范围 | 必须执行哪些正常/错误/中断/恢复用例；哪些原生、真实服务或第二人场景适用 |
| 未确认条件 | 谁补工程/脚本/角色/数据；条件不成立时要缩范围或标blocked，不能默认假通过 |
| 非目标 | 明确不新增什么，以及这些非目标不会被拿来当完成率分母 |

没有原始实施指令时，只能说“按当前文档候选范围核对”，不能替用户重建一个更大的授权。ZCode的“完成”也要先关联这张范围表，才能判断是否过度声明。

## 2 把“有实现”和“已验收”拆开

对每项被选中义务分别记录，不使用一个done覆盖整包：

| 状态维度 | 可以写什么 | 所需证据 |
| --- | --- | --- |
| 实现 | 缺失／部分／已接入 | 实际入口、调用链、文件和改动范围；页面或函数存在只够这一层 |
| 自动验证 | not_run／blocked／failed／passed | 精确命令、目标快照、退出码、完整结果和覆盖断言；有测试文件不等于已运行 |
| 原生验证 | 不适用／not_run／blocked／failed／passed | 真实目标构建、系统/主题/尺寸/输入法、步骤和可定位观察；浏览器或mock不替代适用原生项 |
| 实际使用 | 不适用／未试／有问题／满足本次目标 | 选定真实或等价样本，能核对预期输出；若本次选接手目标，再核对接手者能否继续 |
| 结论 | 本义务完成／部分交付／未完成 | 满足本次约定的所有适用维度，列明仍未覆盖及其是否阻塞 |

不是每个任务都要发布、第二人审批、真实Agent或全部原生组合。只对本次选定目标确定“适用”。另一方面，适用但未测不能被简单改成“不适用”来关闭工作。

### 每个passed至少有这些字段

1. 断言ID与需求/范围版本。
2. 输入夹具、操作步骤和事先写好的预期。
3. 实际结果，包含必要的文件字节/回执/进程终态/错误；不能只写“页面正常”。
4. 目标代码/构建身份、环境、执行时间、命令及退出码（若适用）。
5. 证据位置和复查方法；附件不存在时如实说只有文字记录。
6. 仍未覆盖的异常路径，以及是否影响本次交付。

例如“B3提示可见”只能关闭提示断言，不能关闭持久化、重复关联、非法关联和CLI失败处理。“C2运行typecheck成功”不能关闭长驻脚本停止、外部进程保护或多工程部分失败。

## 3 本次审计发现的复验方法

下面均为**建议的后续验收**，不代表本次已经执行。优先在隔离夹具和mock传输中验证；真实Agent、外部写入或真实进程停止只有在具体后续任务授权且适用时才运行。不得使用本项目的真实任务、业务数据、凭据或付费模型作随手测试。

### AV01 工程、任务与阅读连续性

- 准备：两个受控工程A/B，任务dirName相同但标题、材料标记不同；受控的迟到读取回复。记录原始资料指纹。
- 操作：A内预览→中央→返回；再A→B→A，期间让旧A响应在B返回。
- 预期：B不显示A任务/正文/事件；同工程展开返回保留当前阅读版和来源位置；项目偏好归各root。
- 必须先明确：跨工程切换后是否要求恢复阅读会话，还是按当前会话契约清空。原PA把切工程与预览返回放在一句，不能自行把“所有缓存永久恢复”当成需求。
- 留证：每次root、任务、正文标记、选中版本及返回位置；记录预期清空与预期保留的层次。

### AV02 原生外框、输入与视觉余项

- 准备：明确构建身份和受控用户配置；列适用系统、IME、窗口宽度和主题。
- 操作：选中范围内逐项测试窗口控件/拖动/resize、焦点/Esc、中文组合输入、草稿、窄宽、主题。
- 预期：每个断言分别通过或保留未测，不能以亮色标题栏通过覆盖深色、IME或阅读状态。
- 留证：原生截图与实际交互结果。没有读屏、权限矩阵或标准评估，不宣称相应合规。

### AV03 阅读与版本/错误恢复

- 准备：静态PRD、设计、有效及损坏JSON/JSONL；可控制的文件候选和读取失败。

- 留证：displayed/latest/baseline指纹、诊断、正文及返回位置。类型检查不关闭本项。

### AV04 生命周期与状态反馈

- 留证：IPC参数、原/后文件与提示，不以一帧乐观UI作成功证据。

### AV05 三种创建入口，尤其普通创建失败

- 留证：每条入口的返回、UI反馈与实际文件。没有真实产物时不宣称PRD已写；已有目录冲突应保留输入并给恢复方式。
