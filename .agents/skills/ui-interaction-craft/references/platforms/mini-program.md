# 小程序

## 先识别宿主

- 确认微信、支付宝、抖音等宿主，以及基础库、渲染层、客户端平台和组件库版本。
- 按宿主官方 API 查询确认、动作选择、Toast、剪贴板、输入和页面离开能力；不把接口名、回调字段或限制视为所有小程序通用。
- uni-app、Taro 等跨端框架按实际构建目标核对适配层；统一调用接口不代表所有宿主具有同样的展示、取消和权限行为。
- 不假设 WXML / WXSS、其他模板语言或新渲染层具备浏览器的 `document.body`、DOM Portal、ARIA、hover 和全部 CSS 动画能力。
- 原生能力与自绘组件的层级、覆盖和事件行为分别验证；只有明确需要且受支持时才使用对应的原生覆盖机制。

## 宿主交互

| 任务 | 处理方式 |
| --- | --- |
| 简单重要确认 | 使用宿主确认能力，分别处理确认、取消、外点关闭和调用失败 |
| 少量动作选择 | 使用宿主 ActionSheet 或现有组件，检查选项结果与取消 |
| 短成功反馈 | 使用宿主 Toast 或现有组件，按当前文本、时长与图标限制呈现 |
| 需要修正的错误 | 页面内持久警示、字段错误和恢复动作，不只使用短 Toast |
| 复杂配置表单 | 独立页面或完整任务流程，避免塞进系统提示框 |
| 权限请求 | 由真实宿主授权能力完成，自绘说明与实际授权结果分别处理 |

- 宿主组件的展示成功或 `success` 回调不等于用户确认或业务成功。
- 微信 `showModal` 按结果中的 `confirm` 等字段确认决定；`showActionSheet` 的 `tapIndex` 表示选项，仍需执行业务动作并检查结果。其他宿主查询各自契约，不按相同字段处理。
- 没有明确肯定选择时，不执行确认操作。取消作为正常退出处理，不连环重复弹出。
- 检查按钮文案、选项数量、图标、时长及输入能力限制；内容表达不下时改用合适页面，不截断关键动作含义。
- 宿主 Toast 不支持重试或焦点停留时，将恢复动作放进页面；不能仅为复刻网页行为反复覆盖系统提示。

## 输入与尺寸

- `rpx` 是适配单位，不等于 CSS px、pt 或 dp；结合设备宽度和宿主能力检查实际命中范围。
- 顶部宿主控件、安全区、状态栏与键盘占位按实际客户端处理，不使用固定机型偏移猜测布局。
- 必要说明与操作直接可发现；触控页面不依赖 hover，长按不作为唯一入口。
- 中文组字、确认候选、软键盘完成动作和换行分别检查，避免确认候选时提交表单。
- 输入获得焦点时字段、错误和主要动作可见；页面滚动、键盘补偿和组件自动定位不重复执行。

## 导航与生命周期

- 页面返回、顶部导航和系统返回由宿主与页面栈处理，不用网页 `popstate` 或 DOM 焦点陷阱模拟。
- 重要草稿及时保留；宿主支持离开提醒时再接入相应能力，不在页面已卸载后尝试弹框阻止离开。
- `onHide`、`onUnload` 及对应宿主生命周期中停止不再需要的局部活动，回调不得更新失效页面。
- 界面关闭不代表服务端任务已取消；返回页面时核对任务真实状态。

## 渲染与滚动

- 流式文本合并数据更新，避免每个字或每帧对整段列表调用 `setData` 等跨层更新。
- 活跃新字的轻量动效使用实际运行层支持的机制；不支持局部模糊时使用清晰、可读的接入方式。
- 自适应展开优先已有折叠组件或受支持布局；不能直接复制浏览器 Grid 插值配方并假设全端生效。
- 阅读位置、返回入口和计数占位保持稳定；原生滚动、触控惯性与程序定位只由一个明确机制协调。
- 系统弹层、原生组件、自绘内容和键盘叠加时，检查实际覆盖、穿透、点击与关闭路径。
