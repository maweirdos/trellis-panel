# 桌面端

## 宿主与组件

| 渲染方式 | 使用机制 | 重点边界 |
| --- | --- | --- |
| Electron / Tauri 等 DOM 界面 | 现有组件、CSS、Portal 与浏览器焦点语义 | 同时检查桌面窗口、WebView 和原生系统界面 |
| Windows 原生 | 项目已有 WinUI 等系统组件 | 对话框窗口归属、系统按钮角色与系统输入 |
| macOS 原生 | AppKit / SwiftUI 等现有组件 | 窗口关联呈现、取消语义与平台默认按钮 |
| Flutter / React Native 等桌面原生渲染 | 当前框架的布局、焦点和动画机制 | 桌面输入与系统宿主边界，不按框架名套用移动端规则 |

桌面任务优先保证鼠标键盘、分栏、多窗口与长文本阅读。小窗口可以重新排列布局，但不因此移除键盘路径或改成手机返回逻辑。

## 窗口与焦点

- 对话框、菜单和提示属于明确的窗口或应用根，继承对应主题与操作范围。
- DOM 浮层使用该应用根的 Portal 和层级令牌，不移到失去主题或受错误裁切影响的节点。
- 多窗口状态更新不无故抢夺当前活动窗口焦点；原触发点失效时把焦点交给合理的后续目标。
- Escape 由统一分发处理最上层有效交互，避免一次按键同时关闭菜单、弹窗与页面。
- 原生对话框使用系统按钮角色和排列。WinUI 的安全关闭动作、AppKit 的默认按钮不能按网页按钮索引或统一左右顺序设置。
- 同一窗口的模态任务按组件能力串行呈现，不能从多个异步入口同时堆出重复确认。

## 鼠标与键盘

- 按钮和图标具有明确名称、hover、按下、禁用与键盘焦点表现；必要操作不只在 hover 时可用。
- 菜单支持键盘进入、选项导航、Escape 关闭和焦点返回；Popover 的箭头、强调态与实际展开一致。
- 快捷键按系统和当前焦点作用域处理，编辑控件中的复制、撤销、选择和方向键不被全局导航抢走。
- 中文组字期间 Enter 不提交；组合输入结束、软换行和快速重复击键分别检查，不用固定延时吞掉合法按键。
- 触屏电脑仍可点击菜单和操作栏；不能仅因设备报告鼠标能力就隐藏触控入口。

## 分栏与标题栏

- 分栏拖动期间无缓动滞后；松手后短促吸附。捕获指针并处理移出、取消、Escape 与组件卸载。
- 取消恢复拖动前宽度和状态；折叠时不提前销毁仍承担取消和捕获职责的手柄。
- 分栏与内容区有各自明确的滚动归属，不引入跨面板横向滚动。
- 窗口标题栏拖动与内容分栏拖动分别实现，不能让内容控件落入不可点击的窗口拖动区。
- Electron 自绘标题栏的交互控件使用适当的 `app-region: no-drag`；该 CSS 规则不适用于普通网页或原生视图树。

## 检查

- 窗口缩放、最大化、不同 DPI 与跨显示器移动后，浮层锚点、边缘阴影和命中区域正确。
- 文本追加、计时数字、返回入口及动态计数不改变外层工作区位置。
- 鼠标滚轮、触控板惯性、键盘与减少动态效果均保持可用。
- 模态关闭后回到所在窗口的合理焦点，系统弹层和子窗口不会与自绘浮层重复提交决定。
