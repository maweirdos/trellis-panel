# 网页端

## 输入与布局

- 区分鼠标键盘、触控与混合输入，不只按 User-Agent 或屏幕宽度判断交互方式。
- 使用语义化按钮、链接、输入和表单；动作不伪装成链接，导航保留浏览器的打开、复制和历史行为。
- 命中尺寸和间距满足项目要求及 WCAG 目标大小规则。WCAG 2.2 AA 的一般目标为 `24 × 24 CSS px`，例外按对应条款判断；触控主操作应结合实际任务扩大命中区域。
- 保留缩放、文字选择、复制和键盘焦点；自定义手势只限制必要区域，不全页禁止浏览器操作。
- hover 与键盘聚焦提供同等说明；触控使用可见标签或点击入口，不能把长按作为重要操作的唯一入口。

## 弹层与焦点

- 模态打开时焦点进入，Tab 与 Shift+Tab 留在其中，背景实际不可操作；关闭后焦点回到合理位置。
- 选择原生 dialog 或已有可靠组件处理焦点、背景隔离和语义，不用仅有遮罩外观的 div 冒充模态。
- 只有实际模态的内容才使用 `aria-modal`。初始焦点依据内容结构、风险和后续流程选择，不能总是自动聚焦首个输入框。
- 非模态 Popover 和菜单允许按任务需要退出焦点，外点与 Escape 的行为一致，不无故抢回焦点。
- 锚点超出可见范围、滚动或窗口变化时重新定位或关闭 Tooltip；触发控件激活后提示不挡住操作结果。
- 原生浏览器 alert / confirm 不作为普通业务反馈组件的默认实现。

## 返回与页面状态

- 浏览器返回使用真实导航历史。只有承担路由语义的编辑任务或覆盖页面才与 URL / 历史状态同步。
- 短 Tooltip、菜单和一次性反馈不制造无意义的历史条目。
- 不能用全局返回拦截替代所有弹层关闭逻辑，也不能让页面和容器各消费一次同一返回事件。
- 重要草稿持续保留；`beforeunload` 仅作辅助保护，不作为移动浏览器中防止内容丢失的唯一手段。
- 刷新、前进后退和恢复页面时，按上下文恢复输入、阅读位置和真实任务状态。

## 移动浏览器

- 少量选项可用可触达的 Popover、选择页或底部选择面板；复杂表单优先独立页面，保留浏览器返回的清楚语义。
- 不把桌面居中弹窗等比例缩小。内容过长、横屏或大字号时，主要操作仍可到达。
- 软键盘弹起后检查实际可视区域，必要时使用 Visual Viewport 等能力；不假设固定高度或某个 viewport 单位自动解决所有键盘遮挡。
- 固定底栏结合安全区与键盘状态处理，避免重复加入底部补偿；输入焦点、错误与主操作不被覆盖。
- 测试浏览器地址栏展开收起、方向变化和触控惯性，避免整页用手势动画模拟原生返回。

## 滚动与渲染

- 在真实滚动容器保留滚动槽位或采用组件已有补偿，不全局猜测 body 内边距。
- Web 支持时使用 Grid `0fr → 1fr` 展开，内层正确处理最小高度与裁切；不测写思考框高度。
- 字体和实际字形支持等宽数字；`text-wrap: pretty`、安全区和其他 CSS 能力先核对目标浏览器支持。
- 批量处理文本和尺寸变化，不交错重复读写布局，不为每个新字重复启动平滑滚动。
